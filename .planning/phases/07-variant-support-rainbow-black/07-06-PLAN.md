<objective>
Owner gap 1 (07-HUMAN-UAT.md "## Gaps"): the Black variant becomes 7 suits (five colours + Rainbow + Black), so the board must fit a seventh suit column. This plan does the board side FIRST, before the engine change in 07-07, so the reservation is already wide enough when Black starts dealing 7 suits and no e2e geometry test goes red between plans.

**Owner decision (binding, 2026-09-18, verbatim): "just widen the board a bit to make space for black in that format".** Make room for the 7th column by WIDENING the board. Keep the current tile size and the column format exactly as they are. Never shrink rank slots, columns or tiles. Width is the axis to spend. The board must still fit a 1280x720 window with no horizontal or vertical scroll, and must still scale up via `apps/web/lib/board-zoom.ts` on larger windows. `computeBoardZoom` depends only on the viewport-to-1280x720 ratios, not on board width, so the widening leaves it untouched. The gap-11 scale-up e2e test must stay green.

Board-fit strategy (confirmed by measurement in Task 1): the suit columns sit side by side horizontally, so a seventh column costs WIDTH only (one 50px slot plus one 4px gap = +54px: `playColumnWidthPx(6)` = 328 -> `playColumnWidthPx(7)` = 382). Heights do not change at all, so the 1280x720 vertical slack (~10px) is untouched. The widening is done through `PLAY_AREA_WIDTH_PX` (= `playColumnWidthPx(MAX_SUITS)`), which Table.tsx applies inline to the Play region. The `tableau` board panel (`<section data-testid="tableau">`) has no fixed width of its own. It is a flex row sized by its three regions, so it widens by the same +54px automatically, and no component edit is needed. If Task 2 finds that any component or e2e pins the old 328px Play width or the old tableau width, update that width in the same task. Never touch a tile-size expectation. The tableau's reserved width becomes roughly 8 + 382 + 16 + (101 + 16 + 140) + 8 = about 671px, against a 1280px viewport and the 1024px "stays usable" check, so there is ample horizontal room. **Tiles are NOT shrunk:** `RANK_SLOT_WIDTH_PX`/`RANK_SLOT_HEIGHT_PX` stay 50x65, and no other region (tokens, deck counter, compact discard) is narrowed. The owner has repeatedly said the board is too small; nothing here makes anything smaller. **STOP condition (owner-mandated):** if the widened board cannot fit the 1280px floor without shrinking tiles, the executor must STOP. That covers any horizontal or vertical scroll at 1280x720, any column clipped by the Play region, or a tableau right edge past 1280. There is no shrinking and no fallback, and nothing further is committed for that task. Report the measured numbers (tile size, each region's width, board width, overflow px) so they can go back to the owner. Apply the same stop if the Task 1 baseline already contradicts the arithmetic above.

Purpose: seven columns fit at full tile size, proven in a real browser.
Output: a permanent measurement spec, `MAX_SUITS = 7`, updated layout unit tests, a UI-SPEC addendum.
</objective>
