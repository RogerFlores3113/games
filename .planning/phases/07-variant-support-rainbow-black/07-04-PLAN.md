<objective>
Prove Rainbow and Black end to end through the real UI and server: a Rainbow gameplay e2e exercising the new colour row and the rainbow ring semantics (D-18), a live gradient check (D-11), and the UI-10 full-game test parametrized across base, Rainbow and Black (D-17).

D-18 mechanism decision (Claude's discretion, within the hard constraint): the zero-code route — start a 3-seat Rainbow game and retry room creation until the active player can see a rainbow tile in a teammate's hand. Justification: it adds no production and no dev-only code, so T-07-02 (a deck/seed override reachable in production) cannot exist, and WR-07 (secret seed) is untouched. Odds: the active player in a 3-seat game sees 10 of 60 cards, 10 of which are rainbow, so P(no visible rainbow) = C(50,10)/C(60,10) ≈ 0.13 per attempt; with up to 6 attempts the failure rate is about 5e-6. A dev-var hook was rejected because it would add an env-gated code path to the worker for test convenience only.

Output: e2e/variant-rainbow.spec.ts (new), UI-10 in e2e/start-game.spec.ts parametrized.
</objective>
