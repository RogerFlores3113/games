<interfaces>
The rules-side view type (created in parallel by Plan 01, packages/rules/src/forehead-card.ts). This schema must accept exactly this shape and nothing more:
- HiddenCardView = { id: string; hidden: true }
- VisibleCardView = { id: string; hidden: false; value: ForeheadCardValue }   (ForeheadCardValue is a string union of 16 star names)
- ForeheadCardView = { yourCard: HiddenCardView; otherCards: Array<{ seatId: string; card: HiddenCardView | VisibleCardView }>; revealed: Array<{ id: string; seatId: string; value: ForeheadCardValue; correct: boolean }>; deckCount: number; activeSeatId: string; isYourTurn: boolean; score: number }
- The adapter id is "forehead-card". For an unknown viewer the adapter emits yourCard { id: "unseated", hidden: true }.

Existing (packages/schema/src/messages.ts):
- ErrorMessageSchema = z.strictObject({ type: z.literal("error"), code: RefusalReasonSchema, detail: z.string().optional() })
- encodeServerMessage(msg) parses with ServerMessageSchema then JSON.stringify.

Existing config facts:
- packages/schema/package.json "exports" has only ".": "./src/index.ts"
- tsconfig.base.json "paths" has exact keys "@games/schema" and "@games/rules"
- vitest.config.ts has four projects (schema, rules, worker, web), each with resolve.alias object keys "@games/schema" and "@games/rules" (worker also has "cloudflare:workers"). Vite alias matching treats a string key as matching the key itself OR key + "/..." prefix, in insertion order, so a subpath key must be inserted BEFORE "@games/schema" or it is swallowed by the generic key.
