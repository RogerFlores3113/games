# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope guardrail (read first):** This phase's UI surface is a throwaway toy screen (`ForeheadCardGame.tsx`, replacing `CounterGame.tsx`), deliberately kept at the same bare fidelity as the Phase 1 counter placeholder. It exists to give the redaction chokepoint (HIDE-01…HIDE-04) something real to hide and gets deleted in Phase 4; real board design is Phase 6 (UI-01…UI-11). **No new palette, typography, spacing, or component-library work happens in this phase.** Every token and component below is inherited unchanged from `.planning/phases/01-room-transport-skeleton/01-UI-SPEC.md` — this document only maps those existing tokens onto the toy's new screens/states and adds the toy-specific copy the redaction test needs. This spec was produced in `--auto --chain` mode; all questions below were answered from CONTEXT.md, RESEARCH.md, and the Phase 1 contract with no new user interaction required.

## Typography

**Identical to Phase 1's declared scale — reused via existing `--text-*` CSS custom properties. No new sizes or weights.**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.5 |
| Heading | 24px | 600 (semibold) | 1.2 |
| Display | 40px | 600 (semibold) | 1.2 |

**Toy-specific role mapping (not new sizes — reuses the four above):**
- Revealed card values / other seats' visible card values → **Heading** role, `--color-text` (mirrors `CounterGame.tsx`'s use of Display for its single number; Heading is used here instead of Display because Display stays reserved for the room code per Phase 1's contract, and the toy renders multiple simultaneous card values rather than one hero number).
- Turn indicator, deck count, score → **Body** role.
- Seat labels above each card → **Label** role, `--color-text-muted`.

Only two weights exist (400, 600) — unchanged. No third weight or typeface introduced.

## Color

**Palette unchanged from Phase 1's dark "fireworks night" tokens (`--color-bg`, `--color-surface`, `--color-accent`, `--color-destructive`, `--color-text`, `--color-text-muted`, `--color-border`, `--color-status-connected`, `--color-status-disconnected`). No new hex values this phase.**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0F1A` (`--color-bg`) | Toy screen background, matching every other Phase 1 screen |
| Secondary (30%) | `#141A2E` (`--color-surface`) | Face-down own-card placeholder fill, other-seats' card tiles, revealed-pile strip background |
| Accent (10%) | `#F5B942` (`--color-accent`) | **Reserved for, this phase specifically:** the active guess-value button (enabled state, accent fill + `--color-bg` label per Button contract), the turn indicator text when it is the viewer's own turn, and the "you are here" seat label ring inherited unchanged from Phase 1's SeatRow pattern. Nothing else in the toy uses accent — the face-down placeholder is explicitly NOT accent-colored (see Component Notes: a gold/accent placeholder would visually imply "this is special/actionable" when its entire point is "this is hidden and inert"). |
| Destructive | `#F0453D` (`--color-destructive`) | Not used by this phase's toy — no destructive/error-state UI exists in the toy screen itself (validation failures per D-07 surface as an `error` frame, handled by the existing Phase 1 error/refusal pattern, not a new toy-specific destructive element) |

**Toy-specific tokens (reused, not new):**

| Token | Value | Usage |
|-------|-------|-------|
| `--color-text` | `#F4F6FB` | Visible card values (other seats'), score, deck count |
| `--color-text-muted` | `#8B93A8` | Seat labels, "waiting for {name}" turn text, disabled guess buttons |
| `--color-border` | `#232B45` | Card tile borders (both face-down and face-up), revealed-pile divider |

**Own-card face-down placeholder (HIDE-01/HIDE-03 visual requirement):** rendered as a `--color-surface` filled tile with a `--color-border` outline and **no glyph, number, or icon inside it** — an empty tile, not a "?" or card-back pattern that could be mistaken for a value hint. This is a deliberate visual contract, not just a wire contract: the placeholder must convey "nothing to see" at a glance, consistent with the underlying data structurally lacking the `value` field (D-05). Do not add a card-back illustration; that is Phase 6 scope and would be wasted work given this screen's Phase 4 deletion.

**Contrast rule:** unchanged from Phase 1 — accent fills always pair with `--color-bg` text/labels (≈10.9:1, WCAG AA pass), never `--color-text` (≈1.63:1, fails AA). Applies to the enabled guess-value buttons, which reuse `Button variant="primary"` unmodified.

**Accent reserved for (explicit list, this phase):** enabled guess-value button fill, own-turn indicator text, "you" seat ring (inherited). No other element in the toy screen uses accent.

| Guess control group heading | "Guess your card" (only rendered/enabled on the active player's own turn; per RULES-11-style precedent from REQUIREMENTS.md, disabled entirely rather than hidden for non-active players so the control's existence and its currently-inert state are both visible) |
| Guess button label | Bare value, e.g. "0", "1", "2"… one button per possible value in the toy's declared range (Claude's discretion per CONTEXT.md D-01 — exact range is a `packages/rules` implementation detail, not a UI concern; button set renders however many values `foreheadCardGame` declares) |
| Revealed pile / score heading | "Revealed" |
| Revealed pile empty state | "No cards revealed yet" (shown before the first guess of the game) |
| Deck count | "{n} left in deck" |

| End-of-game body | "Final score: {score}" — reuses the `revealed` list already visible during play (per RESEARCH.md Pitfall 4: no new "reveal all" screen, no exposure of any still-hidden value; the end state renders the same `revealed` list plus the numeric score, nothing else) |

## Screens & States (Phase 2 scope)

Single screen: **`ForeheadCardGame.tsx`**, rendered in place of `CounterGame.tsx` once `view.status === "in_progress"` (same mount point as Phase 1, `RoomClient.tsx` unchanged). Reuses the Phase 1 page shell (centered flex column on `--color-bg`, `3xl` vertical offset) established by `CounterGame.tsx`.

Layout, top to bottom:

1. **Turn indicator** (Body role) — accent-colored text on the viewer's own turn, `--color-text-muted` otherwise. Directly above the card grid, `xl` gap below.
2. **Others' cards row** — a horizontal `sm`-gapped row of face-up tiles, one per other seat, each with a Label-role seat name above it and the card's visible value (Heading role, `--color-text`) inside a `--color-surface`/`--color-border` tile.
3. **Own card** — visually set apart (`lg` gap from the others' row, or a `--color-border` divider) as a single face-down placeholder tile: "Your card" label above, empty `--color-surface`/`--color-border` tile with no glyph inside.
4. **Guess controls** — only meaningful, and only enabled, on the viewer's own turn. One `Button variant="primary"` (or `ghost` when disabled — reusing the existing Button component's disabled state, not a new variant) per possible value, laid out in a `sm`-gapped row/wrap. Disabled with the standard Button disabled treatment (per Phase 1's Button component: accent drops entirely to `--color-surface`/`--color-text-muted`, not a faded accent) when it is not the viewer's turn.
5. **Revealed pile / score** — a `--color-surface` strip below the controls, "Revealed" heading (Label role) + either the empty-state copy or a compact list of revealed `{seatId, value}` pairs (Body role), plus the running score and "{n} left in deck" (Body role, `--color-text-muted`).
6. **End-of-game state** — when `checkGameEnd` returns non-null, the guess controls disappear entirely (not just disabled) and are replaced by the "Game over" heading (Heading role) + "Final score: {score}" body, with the revealed pile still visible below exactly as during play (no new reveal-all content, per RESEARCH.md Pitfall 4 guardrail above).

No other screens change this phase. Lobby, join, create-room, and refusal screens are untouched (Phase 1 scope, already approved).

## Component Notes

- **No new shared components required.** `Button` (primary/ghost, unmodified) is reused for guess controls exactly as `CounterGame.tsx` reused it for "+1". If a `CardTile` sub-component is convenient for the executor (face-up vs. face-down variants), it is a local, phase-scoped component under `apps/web/components/` — not a new addition to the Phase 1 design-system contract, and it must not introduce colors, sizes, or weights outside the tokens declared above.
- **Face-down tile is deliberately blank**, not a "?" glyph or card-back pattern — see Color section. This is a small but load-bearing visual rule: a glyph could imply the client possesses *some* signal about the hidden value (rank of mystery, etc.) when the wire contract (HIDE-03) guarantees it possesses none. Keep the placeholder inert-looking.
- **`data-testid` attributes** should follow `CounterGame.tsx`'s existing precedent (`data-testid="counter-value"`, `data-testid="turn-indicator"`) so Playwright specs updated for the toy (per CONTEXT.md D-02: `e2e/start-game.spec.ts`, `e2e/in-progress-arrival.spec.ts`) have stable selectors — e.g. `data-testid="own-card"`, `data-testid="turn-indicator"` (reused), `data-testid="guess-button-{value}"`, `data-testid="revealed-list"`.
- **This screen is disposable.** Per CONTEXT.md D-03 and this document's scope guardrail, do not add animation, iconography, or polish beyond what's specified above — Phase 4 deletes this file, and any investment beyond "prove the redaction contract in a browser" is wasted effort.
