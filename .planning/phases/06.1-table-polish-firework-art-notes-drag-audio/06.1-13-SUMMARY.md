# Phase 06.1 Plan 13: Fly-To Animation (D-21) Summary

**Departing cards (play, misplay, discard) visibly fly from their vacated slot to the matching stack or discard pile on every screen except the dragging player's own drop, built on the shared D-29 live-history diff and skipped entirely under prefers-reduced-motion.**

## What Was Built

**`flyToEventsForTransition`** (`hanabi-flyto-logic.ts`) is a pure function that reuses `liveHistoryEntries` (06.1-04's shared "is this entry new" boundary) to find newly-live history entries, filters to `play`/`discard` entries only (clue and draw entries never produce a fly-to event), and maps each to a `FlyToEvent { cardId, seatId, suit, rank, destination }` — `destination` is `"stack"` for a successful play and `"discard"` for a misplay or a plain discard (misplayed cards are discarded by the engine). An entry whose `cardId` is present in the caller-supplied `suppressedCardIds` set produces no event — this is the dragging player's own drop, sourced from `useHandDrag`'s `droppedCardIdsRef` (06.1-12).

**`FlyToLayer`** (`components/hanabi/FlyToLayer.tsx`) is a `fixed inset-0 pointer-events-none` overlay (`data-testid="fly-to-layer"`, `z-20`, renders before `EndOverlay` in the tree) that:
1. On every `game` commit (`useLayoutEffect`), skips event derivation entirely on the first commit after mount or after `reconnecting` flips true->false (baseline is `null` until then) — matching D-29's no-catch-up contract exactly.
2. Otherwise calls `flyToEventsForTransition` against the previous commit's history, the current suppression set, and a `prefers-reduced-motion` check (`window.matchMedia`) that, when matched, skips spawning any ghost at all.
3. For each event, looks up the card's previously-snapshotted rect (own-hand slots via `[data-card-id]`, teammate cards via `[data-testid^="other-hand-card-"]`) as the source, and the destination stack (`[data-testid="played-stack-<suit>"]`) or discard pile (`[data-testid="discard-pile"]`) rect, then renders a 48x64 `FireworkCardFace` ghost (`data-testid="fly-to-ghost"`) that CSS-transitions (`.fly-to-ghost`, 450ms) center-to-center from source to destination and is removed after 500ms (timer cleared on unmount, closing T-06.1-40).
4. Re-snapshots every own/teammate card rect at the end of every commit (not just live ones) so the next transition's source rect is always "where the card was just before it left."

Wired into `HanabiBoard.tsx` as `<FlyToLayer game={game} reconnecting={reconnecting} suppressedCardIds={drag.droppedCardIdsRef} />`, placed just before `EndOverlay`.

**`globals.css`** gained `.fly-to-ghost { transition: transform 450ms ease-in-out, opacity 450ms ease-in; }` plus a `prefers-reduced-motion: reduce` override (`transition: none; display: none;`) as a second, structural line of defense alongside `FlyToLayer`'s own behavioral skip.
