## Changes after review

1. **Rank-5 center burst enlarged 1.5x.** `BURST_LAYOUTS[5]` in `apps/web/lib/suit-visuals.ts`: center placement scale 0.35 -> 0.525; the four corner placements nudged outward (0.24/0.76 -> 0.22/0.78) so they stay clear of the larger center burst instead of clipping into it.
2. **Rainbow suit is now an actual multicolour gradient**, not a flat single tone. `SuitGlyph.tsx` renders Rainbow's burst path with an SVG `linearGradient` (stops: `--color-suit-red` -> `--color-suit-yellow` -> `--color-suit-green` -> `--color-suit-blue` -> `--color-suit-rainbow`), using only existing `--color-suit-*` tokens (no new hex, per D-11). Each `SuitGlyph` instance mints its own gradient id via React's `useId()` so many rainbow bursts on one card (e.g. all 5 on a rank-5 card) or many cards on a table never collide on the gradient's DOM id. This **overrides** D-08's original "Rainbow is always a flat single-tone fill, never a gradient" rule — the owner explicitly asked for a real rainbow. Rainbow's silhouette (20-spike flat burst) is unchanged, so it still reads as its own distinct shape in the grayscale/colourblind-safe section.
3. **Corner numeral removed at every card size** (48x64 and 64x84/88x112) — rank now reads from burst count only. `FireworkCardFace` no longer renders any visible numeral text. It gained an accessible `title`/`aria-label` of `"{Suit} {rank}"` (e.g. `"Red 3"`) on the wrapper `<span role="img">`, gated by the same `exposeSuit` boolean that already gates `data-glyph` — an own-hand card the viewer isn't supposed to identify never gets this label either, so no new identity leak. The `numeralSize`/`NumeralSize` prop and type were removed from `FireworkCardFace` since there is no visible numeral left to size.
4. Updated `apps/web/lib/firework-card-render.test.ts` (numeral-absence assertions, new accessible-label assertions, new rainbow-gradient and unique-gradient-id assertions) and `apps/web/app/dev/fireworks/page.tsx` (48x64 row now shows the settled "burst count only" rendering with `exposeSuit`, all rows pass `exposeSuit` so the accessible label is visible for review).
5. Searched the repo for anything outside `FireworkCard.tsx`/`SuitGlyph.tsx` that depended on the visible numeral (other components, `e2e/*.spec.ts`, other test files): none found. `FireworkCardFace`/`FireworkCardBack` are not yet wired into the live table (that lands in 06.1-09/06.1-10), and no e2e spec references `FireworkCard`, `data-glyph`, or a rendered rank numeral today.
6. **Card back redone as a tile with a picture-frame double outline** (two rounds after full burst-art approval): `CARD_BACK_ART` in `apps/web/lib/suit-visuals.ts` no longer has the unlit-shell diamond emblem or the soft glow arc. First pass: a flat `var(--color-bg)` tile fill plus a single `var(--color-border)` rectangular outline. Owner then asked for a second, inset outline as well ("like a picture frame") — the final version is the tile fill plus TWO concentric `var(--color-border)` rectangular outlines (the outer edge outline, and an evenly-inset inner outline), each rendered as its own evenodd ring layer, with an empty interior and square corners. `CardBackLayer` gained an optional `fillRule` field, and `FireworkCardBack`'s wrapper background changed from `var(--color-surface)` to `transparent` (the SVG's own background rect now owns the fill). Still identical for every card, still carries zero suit/rank signal, and `FireworkCardBack`'s props (`width`/`height` only) and existing test contracts (no `data-glyph`, no `--color-suit-`, no `card-identity`, byte-identical across renders) are unchanged.

Current test: all change requests applied and owner-approved, including the picture-frame card back (owner reply: "approved."). Burst art owner gate closed; final D-31 sign-off comes in 06.1-15.
