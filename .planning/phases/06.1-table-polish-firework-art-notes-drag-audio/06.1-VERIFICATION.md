Root cause, confirmed by direct inspection: `playwright.config.ts` contains an explicit code comment warning that these two tests require dev servers started *with* shortened heartbeat/stale-socket env vars (`NEXT_PUBLIC_HEARTBEAT_INTERVAL_MS`, `SOCKET_STALE_MS`, etc.), and that reusing an already-running plain `next dev`/`wrangler dev` process (which is exactly what is running on 3100/8787 in this environment, confirmed via `ps aux`: plain `wrangler dev --port 8787` with no `--var` flags) will make these two timing-sensitive tests time out waiting for production-length (30s+) reconnect windows within the test's 25s assertion timeout. This reproduced identically on two separate runs, consistent with a stale-server timing mismatch rather than flakiness or a code defect. The underlying fix (`9acc73d`, `apps/web/lib/room-socket.ts`) was independently inspected and is a real, targeted fix (swaps in a fresh socket via a query-generation bump when `reconnect()` would otherwise be silently ignored mid-backoff) — not a stub. I did not restart the dev servers per the task's explicit instruction to leave them running, so I could not get a byte-for-byte clean local Playwright run, but the failure signature matches the documented, known-environmental cause exactly and the SUMMARY's own gate (run without a stale pre-existing server) reported these 2 as passing (31/31).
