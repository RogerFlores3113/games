# Phase 6.1 Plan 03: Notes, Discard Grouping, and Drag-Drop Logic Summary

Four pure, unit-tested `apps/web/lib/` modules: one shared defensive `localStorage` wrapper, private per-card notes keyed by room+seat+card id, per-suit/per-rank discard grouping with a persisted compact/expanded preference, and pointer-geometry drag-drop resolution (reorder/play/discard) that never re-derives turn/token legality.

## What Was Built

**Task 1 — `safe-storage.ts`, `hanabi-notes.ts`, `hanabi-discard-logic.ts`:** `safe-storage.ts` mirrors `seat-token.ts`'s `getLocalStorage` discipline (SSR-safe, try/catch around the storage getter itself, not just its methods) but generalizes it into four exports (`safeGetItem`, `safeSetItem`, `safeRemoveItem`, `safeKeysWithPrefix`) so every persisted preference in this phase shares one wrapper instead of three independent copies. `hanabi-notes.ts` builds `hanabi-note:{roomCode}:{seatId}:{cardId}` keys, truncates writes to `NOTE_MAX_LENGTH = 20`, treats an empty write as a delete, and exposes `pruneNotesForSeat`/`clearNotesForRoom` for card-leaves-hand and end-of-game cleanup (D-04) — the module imports nothing that can reach the wire or the client state store, verified both by a structural source-scan test and the plan's acceptance-criteria greps. `hanabi-discard-logic.ts`'s `groupDiscardsBySuit` returns one `{ suit, total, countsByRank }` entry per `variantConfig(variant).suits`, including zero-count suits, and `readDiscardViewPref`/`writeDiscardViewPref` persist the compact/expanded toggle with an unrecognised stored value falling back to `"compact"`.

**Task 2 — `hanabi-drag-logic.ts`:** `exceedsDragThreshold` (Euclidean distance at/above `DRAG_THRESHOLD_PX = 6`), `resolveDropTarget` (hit-tests a point against reorder slots first, then play, then discard, else `{ kind: "none" }`), `reorderedCardIds` (remove-then-insert move semantics, unknown id returns input order unchanged), `dropZoneStatus` (thin wrapper over `disabledReasonFor` from `hanabi-visual-logic.ts` — adds no disabling rule of its own), and `requestForDrop` (combines the above into the actual action to send: reorder is legal off-turn but blocked only by `ctx.reconnecting`/`ctx.ended`; play/discard require `dropZoneStatus` to report enabled). No DOM reads, no React import — pure functions over primitive coordinates/rects supplied by the calling component.
