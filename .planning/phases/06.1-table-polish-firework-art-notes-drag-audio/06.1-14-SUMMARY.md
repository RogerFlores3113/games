# Phase 06.1 Plan 14: End-to-End Proofs for Table Polish Summary

**Nine new Playwright tests against the real Cloudflare Worker and Next.js dev server prove every Phase 6.1 user-visible behavior — drag reorder/play/discard, slot-preserving draws, clue marks above cards, private notes, the discard overlay, and no-catch-up audio — plus the UI-11 1280x720 no-scroll fit now covers the new marks-zone/note-row/audio/discard-toggle surface.**

## What Was Built

**Task 1 — Helpers and hand-order/drag/slot proofs:** `e2e/helpers.ts` gained `dragLocatorTo(page, source, target)` (raw `page.mouse` down/move/up with an intermediate 10px move past `DRAG_THRESHOLD_PX` before gliding to the target over 12 steps — never Playwright's HTML5-DnD-oriented `dragTo`), `ownHandCardIds(page)` (reads `[data-testid="own-hand"] [data-card-id]` in DOM order), and `teammateHandCardIds(page, seatId)` (reads `other-hand-{seatId} > [data-testid^="other-hand-card-"]` testids, stripped to bare ids). `e2e/hanabi-table-polish.spec.ts` was created with five tests:
- **HAND-01** — the passive (off-turn) player drags own-hand slot 1 onto slot 3; the resulting order (computed via a locally-duplicated `reorderedCardIds` algorithm, `expectedReorder`) is asserted on the passive player's own hand AND on the active player's view of that teammate's hand, the active turn indicator is unaffected, and both assertions re-hold after both pages reload.
- **HAND-02 (drag-to-play / off-turn no-op)** — an off-turn drag onto the play zone shows `drop-reason-play` while hovering and changes nothing (deck count, hand order) on release; the active player's drag onto the play zone then reduces the deck count, observed from the passive page.
- **HAND-02 (drag-to-discard)** — the active player gives a clue first (dropping clue tokens below 8, since discard is disabled at 8/8), then the new active player drags a card onto the discard pile; `data-discard-count` increments by 1 on both screens.
- **HAND-02 (buttons)** — click-to-select plus the Play button still works, observed via a deck-count drop on the other page.
- **HAND-03** — captures the actor's and the observer's teammate-view hand ids before a button play of slot 2, polls until index 1 changes (not just until the array length is unchanged, which is vacuously true immediately), and asserts every other index is byte-identical on both the actor's own hand and the observer's teammate view.

**Task 2 — Marks/notes, discard overlay, audio, and fit proofs:** Four more tests added to the same spec file:
- **NOTE-01** — the own-hand `marks-zone-slot-1` and a teammate's `marks-zone-{cardId}` both end (bottom edge) at or above their card's top edge (±1px).
- **NOTE-02** — a note typed into `note-chip-slot-1` persists through a reload, never appears in any `framesent` WebSocket payload (captured via `page.on("websocket", ws => ws.on("framesent", ...))`, attached before typing), and resets to the empty `aria-label="Add note"` state once that slot's card is played (a fresh card, and thus a fresh React key, occupies the slot).
- **D-13** — clicking `discard-toggle` opens `discard-overlay`, which stays open across a reload (localStorage-backed preference), closes on Escape, and stays closed across a further reload.
- **AUD-01** — a hand-written `FakeAudioContext` class (installed via `context.addInitScript` on both browser contexts, before any navigation) counts every `oscillator.start()`/`bufferSource.start()` call into `window.__soundStarts`. After a gesture-unlock click on the observer and a live clue from the active player, `__soundStarts` polls above 0 on the observer; after a reload, a fresh gesture-unlock click, and a 1.5s window with no further actions, `__soundStarts` is exactly 0 — proving D-29's reconnect baseline reset holds end to end, not just at the unit level.

`e2e/start-game.spec.ts`'s existing UI-11 test gained five more `toBeInViewport()` assertions at 1280x720: `marks-zone-slot-1`, `marks-zone-slot-1-note-row`, `audio-mute-toggle`, `discard-toggle`, and the first teammate `marks-zone-{cardId}` inside `teammates-band` (scoped to exclude the viewer's own marks zones, which also match the bare `marks-zone-` prefix).

## Deviations from Plan

### Auto-fixed Issues (found and fixed during this plan's own test-writing/debugging, before any commit)

**1. [Rule 1 - Bug in test, not app] `observer.locator("body").click()` did not reliably fire the gesture-unlock listener**

- **Found during:** Writing/debugging the AUD-01 test (Task 2).
- **Issue:** `useHanabiAudio`'s gesture-unlock listener is a `window`-level `pointerdown`/`keydown` handler; clicking the `body` locator's auto-computed center point on this board's `min-h-screen overflow-y-auto` layout did not reliably deliver a pointerdown that unlocked the fake `AudioContext` in every layout state — `window.__soundStarts` stayed 0 even after the gesture click and a live clue. Isolated with a throwaway debug spec (deleted before commit) instrumenting both pages' consoles: `page.mouse.click(5, 5)` at a fixed small-corner coordinate worked reliably where `locator("body").click()` did not.
- **Fix:** Replaced both gesture-unlock clicks in the AUD-01 test with `observer.mouse.click(5, 5)`.
- **Files modified:** `e2e/hanabi-table-polish.spec.ts` (test-only; no application code touched).
- **Verification:** `npx playwright test e2e/hanabi-table-polish.spec.ts -g "AUD-01"` — passed, `__soundStarts` reached 2 after the live clue and reset to 0 after reload.

**2. [Rule 1 - Bug in test] `teammateHandCardIds` looked up the wrong seat id in HAND-01, and HAND-03's poll condition was vacuous**

- **Found during:** First `npx playwright test -g "HAND-"` run (Task 1).
- **Issue (a):** HAND-01's first draft called `seatIdOfOtherPlayer(passivePage)` (the active player's OWN seat id, as seen from the passive page) and then queried `other-hand-{activeSeatId}` on `activePage` itself — a page never renders its own seat as a teammate hand, so the locator matched zero elements and `teammateHandCardIds` returned `[]`. **Issue (b):** HAND-03's first draft polled only `(await ownHandCardIds(activePage)).length === actorIdsBefore.length`, which is true both before and immediately after the play (both 5 cards), so the poll resolved before the server's confirmed post-play frame had actually landed, and the subsequent identity assertion at index 1 failed non-deterministically.
- **Fix:** (a) Changed HAND-01 to `seatIdOfOtherPlayer(activePage)` (the passive player's seat id, as the active page sees it) and query `activePage` for `other-hand-{passiveSeatId}`. (b) Changed HAND-03's poll predicate to require both the length match AND `ids[1] !== actorIdsBefore[1]`.
- **Files modified:** `e2e/hanabi-table-polish.spec.ts` (test-only).
- **Verification:** `npx playwright test e2e/hanabi-table-polish.spec.ts -g "HAND-"` — 5/5 passed after the fix.
