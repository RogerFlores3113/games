# Phase 6.1 Plan 04: Audio Cue Logic and Synthesis Engine Summary

**Pure, unit-tested modules for AUD-01: a shared live-history diff, a single-precedence cue selector (fuse > stack-complete > play), and an injectable Web Audio engine with 5 synthesized tile-tap recipes and persisted mute/volume prefs — no wiring into the board yet (that's 06.1-08).**

## Accomplishments
- `liveHistoryEntries` establishes the D-29 "no catch-up" baseline as a single shared function (also the intended source for 06.1-13's fly-to animation)
- `cueForEntry`/`cuesForTransition` select exactly one cue per live history entry, with fuse and stack-completion taking precedence over a plain play cue, reusing `newlyCompletedStacks` rather than re-deriving completion
- `createAudioEngine` is fully gesture-gated (no context/nodes before `unlock()`), mute/volume-gated, and never throws even if `AudioContext` construction fails — verified against a hand-written fake context recording every node and ramp call
- `CUE_RECIPES` defines 5 pairwise-distinct tone+filtered-noise recipes (clue, play, discard, fuse, stack-complete), each layer with attackMs >= 2, decay > attack, and peak gain <= 1
- `readAudioPrefs`/`writeAudioPrefs` persist mute/volume through the existing `safe-storage.ts` wrapper, clamping untrusted stored values into [0,1] (T-06.1-13)

## Decisions Made
- Renamed the tone-layer's waveform field to `shape` rather than `wave`/`waveform`, since both of the latter contain the substring `.wav` and would false-positive the plan's own acceptance-criteria grep for audio file extensions (`\.mp3|\.ogg|\.wav|fetch\(`). Purely a naming fix — behavior and recipe design are unaffected.
- `createAudioEngine` reads `readAudioPrefs()` once at construction time for its initial `muted`/`volume` state, then keeps them in closure state, writing back through `writeAudioPrefs` on every `setMuted`/`setVolume` call — matches the plan's described dependency-injectable engine shape without adding a second prefs-reading path.

### Auto-fixed Issues

**1. [Rule 1 - Bug] Renamed SoundLayer's tone field from `wave`/`waveform` to `shape`**
- **Found during:** Task 2 (Web Audio engine implementation)
- **Issue:** The plan's own spec named the field `wave: "sine" | "triangle"`. This field name, and the `waveform` alternative first tried, both contain `.wav` as a literal substring (`layer.wave`, `layer.waveform`), which trips the plan's acceptance-criteria grep `grep -nE "\.mp3|\.ogg|\.wav|fetch\(" apps/web/lib/hanabi-audio-synth.ts` — a grep meant to catch accidental audio-file usage, not a legitimate field name.
- **Fix:** Renamed the field to `shape` throughout `hanabi-audio-synth.ts` (type definition, all 5 recipes, and the `osc.shape` assignment site) and the corresponding test file.
