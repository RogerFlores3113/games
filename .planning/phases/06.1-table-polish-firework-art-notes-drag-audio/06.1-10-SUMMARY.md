# Phase 6.1 Plan 10: Stack and Discard Art Composition Summary

Stack heads on the table now render the owner-approved firework burst art (rank from burst count only, no numeral, per the 06.1-07 owner gate), and the discard pile defaults to a compact per-suit/per-rank count view with a toggle that opens a new `DiscardOverlay` full-art modal — the open/closed preference is remembered per browser via `hanabi-discard-logic.ts`, and the compact view keeps the discard pile from growing the table past the 1280x720 no-scroll fit as the game progresses.

## What Was Built

**Task 1 — `DiscardOverlay.tsx`:** A `fixed inset-0` scrim + `role="dialog"` panel component, shaped like `EndOverlay.tsx` (scrim `onClick={onClose}`, panel stops propagation, close button focused on mount, a window `keydown` listener closing on Escape and removed on unmount). Body groups discarded cards by suit via `groupDiscardsBySuit` (only suits with `total > 0`, cards within a suit sorted by rank), rendering each as a `FireworkCardFace` (48x64, no `exposeSuit`) plus an sr-only `"{Label} {rank}"` span, wrapped in a `data-testid="discard-overlay-card"` element. Empty state shows "No cards discarded yet". Render-tested against the plan's three behavior bullets (dialog shell + empty state, suit-grouped card count with red-before-blue ordering, close-button label/testid).

**Task 2 — Table.tsx stack heads and discard composition:** Stack heads with `topRank > 0` now render `<FireworkCardFace suit rank width={48} height={64} exposeSuit showBurstCount />` (no `numeralSize` — that prop no longer exists per the owner override); `topRank === 0` stacks keep a faded (`opacity: 0.35`) `SuitGlyph` plus a "—" dash, preserving exactly one `data-glyph` per stack either way. The discard block gained `data-discard-count={game.discard.length}` and `data-view={view}` on the existing `discard-pile` testid, a mount effect reading `readDiscardViewPref()` (initial state `"compact"` for SSR safety), a compact header row ("Discard" label + an icon-only `discard-toggle` button, lucide `Layers`, `aria-label="Show full discard pile"`), and per-suit compact rows (`SuitGlyph` size 14 + `"{rank}×{count}"` tokens for ranks with a nonzero count). Clicking the toggle sets `view` to `"expanded"`, persists it via `writeDiscardViewPref`, and renders `<DiscardOverlay>` (closing resets to `"compact"` and persists that). `e2e/start-game.spec.ts`'s two `[data-testid="discard-pile"] li` counts were replaced with reads of the new `data-discard-count` attribute.

## Deviations from Plan

### Owner-decision adaptations (per owner_decisions_override_plan)

**1. `numeralSize` omitted from the stack-head `FireworkCardFace` call**
- **Context:** The plan's Task 2 `<action>` text (written before 06.1-07's owner gate closed) specifies `numeralSize="label"`. Per 06.1-07-SUMMARY.md and 06.1-09-SUMMARY.md, `FireworkCardFace` no longer has a `numeralSize` prop at all — rank reads from burst count only, everywhere, with no visible numeral.
- **Fix:** Stack heads call `<FireworkCardFace suit rank width={48} height={64} exposeSuit showBurstCount />` with no `numeralSize` argument (the prop does not exist on `FireworkCardFaceProps`; including it would fail `tsc -b apps/web`).
- **Verification:** `npx tsc -b apps/web` exits 0.

### Auto-fixed Issues

**1. [Rule 3 - Blocking] UI-11 no-scroll fit regressed after adding the discard-toggle button's 44px touch target**
- **Found during:** Task 2 verification (`npx playwright test e2e/start-game.spec.ts -g "UI-11"`)
- **Issue:** A literal `min-height: var(--size-touch-min)` (44px) on the new `discard-toggle` button grew the compact discard header row well past the plain "Discard" label it replaced, pushing `document.documentElement.scrollHeight` to 744px against a 720px viewport (measured via a temporary diagnostic `console.log`, then removed).
- **Fix:** Kept the button's visible/flow box icon-sized (16x16, matching the label row's own height) and added a separate absolutely-positioned `aria-hidden` inset span sized to the full 44px touch target via `inset: calc((var(--size-touch-min) - 16px) / -2)`. The out-of-flow span still receives and bubbles click events (it is rendered inside the button), so the touch target itself is unchanged — only the row's contribution to document flow height shrank back to the label's own size.
- **Files modified:** `apps/web/components/hanabi/Table.tsx`
- **Verification:** `npx playwright test e2e/start-game.spec.ts -g "UI-11"` passed (scrollHeight 721 vs innerHeight 720, within the test's 1px tolerance); full `npx playwright test e2e/start-game.spec.ts` and `npx playwright test e2e/hanabi-realtime.spec.ts` re-run afterward.
- **Committed in:** `a62bf0e` (Task 2 commit)
