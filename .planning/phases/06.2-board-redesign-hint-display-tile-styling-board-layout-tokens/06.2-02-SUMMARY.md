## Decisions Made

- Used CSS keyword `black` instead of a `#000` hex literal as the `color-mix()` darken input for `.board-surface`, keeping the wooden-texture rule fully inside the no-hex-outside-`@theme` rule without needing a documented literal-value exception (unlike `.table-backdrop`'s rgba scrim, which needed one because rgba can't be built from a keyword the same way).
- Reworded the tile-preset group's doc-comment mention from `` `--color-tile-preset-*` `` to "the four tile-preset tokens below" so the acceptance-criteria grep (`grep -c -- '--color-tile-preset-'` must equal 4) counts only the four real declarations, not the comment's own group mention — same self-referential-grep discipline the codebase has hit before (per STATE.md's `hanabi-notes.ts` precedent).
- `TEAMMATE_BAND_PX`/`OWN_BAND_PX` are asserted as fixed values (140/180) plus "no `MARKS_BAND_PX` export exists", rather than a strict component-sum equality, because the UI-SPEC's own listed own-hand sub-components (turn indicator 24 + card 100 + controls 44 + note-row 20 = 188) already exceed its stated 180px band total — the source figures assume some row overlap, so enforcing arithmetic equality would encode a false invariant.
