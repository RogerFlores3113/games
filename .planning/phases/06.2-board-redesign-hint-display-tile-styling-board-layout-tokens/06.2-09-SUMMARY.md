# Phase 06.2 Plan 09: Drag Shift-Aside Summary

**During an own-hand drag reorder, the other tiles now visibly slide aside via a `.tile-shift` transform to open a gap at the current drop position, computed by a new pure `shiftOffsetsForDrag` function and consistent with the eventual submitted reorder.**

## Accomplishments
- `shiftOffsetsForDrag(handIds, draggedId, targetIndex, slotPitchPx)` added to `hanabi-drag-logic.ts`, fully unit tested (7 new test cases including a reorderedCardIds-consistency property check across every dragged id / target index combination for a 5-card hand)
- `useHandDrag`'s `dragState` now surfaces `dropIndex` (derived from the existing reorder target) and a measured `slotPitchPx` (from the already-registered slot rects, sorted by physical left position) — no new listener, no new measurement mechanism

## Decisions Made
- `shiftOffsetsForDrag` accepts `draggedId: string | null` (rather than requiring a sentinel non-member id) so "no drag in progress" is a first-class, natural input rather than a caller-side special case — matches the "no drag" behaviour bullet directly.
- Slot pitch is measured by sorting registered rects by physical `left` position rather than relying on `slotsRef`'s `Map` insertion order, since that Map's key order can go stale relative to a mid-drag optimistic reorder (new keys are appended, not reinserted in position).
- The shift wrapper `<div>` is `inline-block` with no padding/margin so it adds zero flow height/width — verified directly by the UI-11 e2e fit check staying green, not just visually assumed.
