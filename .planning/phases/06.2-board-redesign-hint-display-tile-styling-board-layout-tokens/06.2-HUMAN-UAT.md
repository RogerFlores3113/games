## Sign-off checklist prepared for the owner (from this phase's own testing and SUMMARYs)

### Two bugs found during this phase's own testing (fixed, for the record)

1. **Three controls were unclickable by mouse in production.** The keep-hints toggle, the tile-colour-picker toggle button, and every tile-colour swatch button had their enlarged (44px) touch-target hit area implemented as a sibling `<span>` painted after the button, which silently sat on top of the button and swallowed every mouse click — not just a Playwright artifact, a real production bug. Fixed by moving each overlay span to be a descendant (last child) of its button instead, matching the one control (`discard-toggle`) that already did this correctly. Commit `3d1a919`.
2. **The 6-colour Rainbow/Black variants broke the 1280x720 no-scroll fit.** `CluePicker`'s value row grows by one button per cluable colour (6 for Rainbow/Black vs 5 for base); at 5 players and 1280px width the extra button pushed the sibling audio/toggle controls onto their own extra wrapped line, breaking the fit specifically for the two box variants this phase exists to support. Fixed by reordering the bottom-controls-row children so `CluePicker` (the only element whose width scales with variant suit count) is always the row's last child, guaranteeing it wraps onto its own line regardless of suit count. Commit `27406d9`.

### The UI-11 fit regression and its real cause

The always-visible note box's input had no explicit width, so the browser gave it its intrinsic default text-input width (~200px) instead of the 88px tile width beneath it. That made the whole own-hand row render 862px wide instead of ~410px, which pushed the clue picker/card actions/audio controls onto extra wrapped lines purely by width, not by any real height need — 847px page height against a 720px viewport. Fixed by giving the note box's container and the per-card hand slot an explicit 88px width instead of `w-full` (commits `705b65a`, `7a092df`). The layout-budget ledger (`apps/web/lib/layout-budget.ts`) was corrected to the measured reality rather than left with numbers that only made an arithmetic-only test pass without reflecting the real render: `OWN_BAND_PX` 180 → 300, `BOARD_CHROME_PX` 40 → 16.

### A behaviour change the owner must decide on

The expanded discard-pile overlay no longer groups tiles by suit. A single shared, draggable discard order (any player can rearrange it, and everyone sees the same arrangement — DISC-01) cannot coexist with an automatic suit-grouped presentation, since the server only stores one order. The overlay now shows the shared arrangement only, with no suit grouping. **Ask the owner explicitly:** is a single shared order with no suit grouping acceptable, or do they want a "group by suit" action that re-sorts the shared order for everyone (a visible, shared re-sort, not a private view)?

### Worst case measured

5 seats, Black variant (6 cluable colours, the largest clue-picker row), a 30-tile discard pile, and advanced played stacks — 1280x720, no scrolling. Measured live: `teammates` band 117px, `tableau` 282px, bottom controls row 309px, page total exactly 720px (zero slack).

## Gaps

The owner rejected this review ("no, bad job") — every item below is a **defect** in what this phase delivered, not a new feature request. The automated gate was fully green (846 unit, 40 e2e, clean typecheck) throughout; none of these were catchable by that gate — they are visual/interaction judgements only a human review surfaces. Each is listed as its own discrete entry so a gap-closure planning pass can pick them up one at a time.

1. **Fixed board geometry.** Every board area must reserve its space up front. The board must not grow or reflow as tiles accumulate — content fills pre-portioned space, not the other way around.
2. **Board colour and texture.** The board is still the "gross monotone" from before. It must be dark-wood coloured and textured. Explicitly NOT CSS-generated — source a free, properly licensed image that looks like a real board-game surface, and record author/source/licence in `apps/web/public/backgrounds/CREDITS.md`, as 06.1 did for the table background. This reverses decision D-11.
3. **Play area as a grid.** Each suit is a row or a column, and each next rank sits directly beside or below the previous one, so a stack's progress reads as a filled line in a grid. This replaces the horizontal fan from BOARD-05.
4. **Clue token outline.** Clue tokens need a blue outline, matching how the fuse tokens are already outlined.
5. **Token size.** Clue and fuse tokens should render at 2x their current size.
6. **Remove obtrusive token-count text.** The "{n} clues left" and "{n} fuses left" text on the board is obtrusive and must be removed from the visible board. Keep an accessible equivalent for screen readers and tests, but nothing obtrusive on screen.
7. **Tile-colour overlay is wrong.** The coloured rectangle is supposed to be a semi-transparent, darker overlay on top of the card, so changing the tile colour tints and darkens the card visible beneath it. It currently renders as an opaque layer that hides the card entirely, blocking the colour change from ever being visible against the card art.
8. **Settings relocated to a modal.** Move settings out of the bottom controls row into a dedicated settings modal: a gear icon in the top right opens a centre-justified modal holding tile/card colour, a volume slider, and hint persistence.
9. **Background image.** Replace the current background with an image of a city on the water with fireworks going off in the background, properly licensed and credited (per the same `CREDITS.md` discipline as item 2).

### Gaps 11-16

11. **The board is sized for 1280x720 and looks tiny on a normal monitor.** Every dimension was tuned to the worst case and then shrunk further to fit the vertical stack (rank slots went 40x30 -> 24x20). 1280x720 should be the MINIMUM supported size, not the design target: the board must scale with the viewport so a 1080p or 1440p window gets proportionally larger tiles, while 720p still fits without scrolling.
12. **The tile colour tint is still unfinished** — the coloured rectangle is opaque and hides the card instead of tinting and darkening it. Already scoped as gap 7 / plan 06.2-17.
13. **Play and Discard buttons move above the player's own hand**, not beside or below it.
14. **The player's own hand is always centred**, whatever the seat count or window size.
15. **Delete the disabled-reason text** ("Select a card in your hand first", "Clue tokens are full", and any sibling strings). The affordance should speak for itself.
16. **Replace the clue picker with a quick-clue popover.** Clicking a tile in an opponent's hand pops up two buttons for that tile: the COLOUR clue, whose label text is rendered in that suit's own colour, and below it the NUMBER clue, in bold. Clicking either sends that clue to that player. The large clue menu is removed entirely.
