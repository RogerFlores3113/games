## Accomplishments
- `Table.tsx`'s `tableau` section is now a flex row of three fixed regions: Play (`PLAY_AREA_WIDTH_PX` x `PLAY_AREA_PX`), a Deck-counter+Discard column (fixed `BOARD_INNER_PX` height, `flex: 1` to absorb remaining width), and Tokens (`TOKEN_AREA_WIDTH_PX`) — the panel's own height is fixed at `BOARD_INNER_PX + 2 * BOARD_PANEL_PADDING_PX`.
- New `table-render.test.ts` assertions prove the `tableau` element's inline style is byte-identical between an empty game and a full board (5 suits at rank 5, 30 discards, 0 clue tokens, 0 fuses remaining), and that `discard-pile`'s inline style is identical at 0 and 30 discards.
- New assertion proves the Play region's inline width equals `PLAY_AREA_WIDTH_PX` at both 5 and 6 suits (the Rainbow/Black worst case).
- Removed the deprecated `LEFT_COLUMN_PX` alias from `layout-budget.ts` and the unused `columnHeightPx` prop from `TokenColumn.tsx`, along with both call sites.

## Decisions Made
- Laid out the three regions as `items-start` flex-row siblings (not `items-stretch`), since each region now owns its own fixed height rather than stretching to match a sibling's height — matches the owner's literal "Play at the top, Discard at the bottom... clue and fuse tokens on the right" layout description read as three independent boxes, not two columns.
- Used `flex: 1, min-width: 0` on the Deck+Discard middle column so the board panel's total rendered width is not itself a new hardcoded constant — it's `PLAY_AREA_WIDTH_PX + TOKEN_AREA_WIDTH_PX + gaps + whatever remains`, which keeps the panel width driven by the page layout rather than duplicating a width ledger entry that would need to be kept in sync with the other two.
- Reduced `FireworkCardBack` in the deck counter from 32x44 to 28x38 (per the plan's explicit instruction) so it fits inside the unchanged 40px `DECK_COUNTER_PX` row now that this row sits directly in the flex column rather than absorbing overflow from a taller sibling.

## Deviations from Plan

None - plan executed exactly as written. `PLAY_AREA_PX` was already defined pre-existing in `layout-budget.ts` (== `BOARD_INNER_PX`) and needed no change; only `Table.tsx`'s consumption of the ledger changed.

## Issues Encountered

- The initial `styleFor` test helper threw when an element had no inline `style` attribute at all (React omits the attribute entirely for an empty style object, e.g. an un-highlighted drop zone's `discardHighlight = {}`). Fixed by having `styleFor` return `null` instead of throwing — `null === null` correctly proves "no inline style, at both 0 and 30 discards" rather than being a test bug.
- `apps/web/lib/table-render.test.ts`'s new discard fixture needed `noUncheckedIndexedAccess`-safe suit array indexing (`suits[i % suits.length]!`) and `MAX_FUSES` imported from `@games/rules` (fuses remaining is computed as `MAX_FUSES - view.fuses`, so "0 fuses remaining" required `fuses: MAX_FUSES`, not a literal `0`).
