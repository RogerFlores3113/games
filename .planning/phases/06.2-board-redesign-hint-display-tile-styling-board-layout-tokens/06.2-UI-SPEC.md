## Owner review 2026-09-17 — revisions

The owner rejected this document's first-draft implementation at UAT and, across three review passes (gap-closure plans 06.2-13 through 06.2-21, plus a sixth-review scoped fix, logged in `06.2-HUMAN-UAT.md`), overturned several of its original decisions. This note is the single dated pointer to what changed and why; the sections below are edited in place to describe the board that was actually built, not the one originally proposed. Anything not listed here — the note box, drag shift-aside (DRAG-01), and D-07 ("Let it go," no ruled-out-clue UI) — still stands exactly as originally written. **The hint composition (D-06) is NOT one of those — it was overturned 2026-09-18, see below and "Hint Display System" further down.**

Overturned decisions, by original decision ID:

- **D-11/D-15 (wooden board texture):** the CSS-generated grain-line texture was rejected outright ("don't generate the texture either — find something free online that looks good, looks board game-y") and replaced with a sourced, licensed photograph, later replaced again with an owner-supplied tiled walnut image. See "Wooden board texture" below.
- **D-22/BOARD-05 (fanned played stacks):** the horizontal-fan layout was replaced with one fixed column per suit, five reserved rank slots stacked top to bottom. See "Played stacks" below.
- **Height Budget's two-column model:** the "LEFT COLUMN (Play/Deck/Discard) beside RIGHT COLUMN (tokens)" side-by-side layout was rejected in favor of the owner's literal description — Play at the top, deck count in the middle, Discard at the bottom, all stacked vertically, with the clue/fuse token column to the right of that stack. See "Layout — Height Budget" below.
- **Bottom-band controls:** every non-play preference control (mute/volume, keep-hints toggle, tile-colour picker) moved off the board into a new `SettingsModal.tsx`, reached via a top-right gear trigger. The bottom band now holds only Play/Discard (`CardActions`) and the own hand.
- **Clue-giving UI:** the large `CluePicker` target/value menu is deleted entirely. Clue-giving is now a quick-clue popover opened by clicking the specific opponent tile to be clued.
- **Clue/fuse token sizing and count display:** tokens doubled to 40px discs ("larger by 2x"), and the accessible token-count text moved from always-visible to `sr-only`.
- **Tile-colour presets:** changed from an opaque tile-fill to a translucent overlay painted on top of the card art, so the card identity stays visible under any preset.
- **Viewport handling:** 1280x720 was reclassified from "the design target" to "the minimum supported size" — the board now scales up via CSS `zoom` on larger viewports.
- **Discard ordering:** a new shared group-by-suit re-sort action was added to the Discard area, layered on the existing DISC-01 shared-reorder mechanic.
- **D-13/D-14 (tile-colour picker) — owner-overruled 2026-09-18 (fifth review, UAT gap 30):** the five-preset swatch grid (`TileColorPicker.tsx`) is replaced with a real colour picker — a native `<input type="color">` — so the player can choose ANY colour, not one of five presets. D-14's original contrast concern (every option must stay legible against suit colours/glyphs/hint tints) is preserved structurally rather than by restricting the palette: `tile-color-pref.ts`'s `resolveTileColorCss` wraps whatever colour the player picks in the same low-alpha translucent `color-mix()` wash the presets used (per gap 7), so a chosen colour still only ever tints/darkens the card, never replaces its surface. Verified against the three extremes explicitly called out (pure white, pure black, a saturated colour at full strength) — all three stay translucent. See "Tile colour picker" under Component Notes below.
- **D-06 (hint composition) — OVERTURNED 2026-09-18 (sixth review, UAT gaps 32-35):** the owner rejected the shipped hint mechanics outright ("hint mechanics are broken"). Three changes, all scoped to a fix outside the normal plan sequence (logged in `06.2-HUMAN-UAT.md`'s sixth review):
  - The colour-hint highlight is no longer a translucent `color-mix` wash across the whole tile face (gap 33 — removed entirely) — it is now a thin inset ring drawn in the clue's own `--color-suit-*` hue (gap 32), never the shared yellow `--color-card-glow`.
  - **D-06 itself is overturned:** a card's hint display no longer shows every positive clue it has ever accumulated. It shows ONLY its most recent clue (gap 34) — colour and number are no longer simultaneously composable from two different clues; whichever clue landed last is the only one displayed. (A single clue is still exactly one type, so this is not a loss of information within one clue — it only removes cross-clue accumulation.)
  - **D-08/D-10/D-11's Phase 6 luminosity frame is deleted entirely** (`luminosityStepFor`, `LUMINOSITY_FRAME`, `components/hanabi/luminosity-frame.ts`, `data-luminosity`) — this is UI-08 being superseded (gap 35: "the yellow outline highlight persists indefinitely"). A card's border/box-shadow is now a fixed, non-clue-driven constant; the hint overlay (governed solely by the keep-hints-visible toggle, HINT-03) is the card's ONLY clue-driven visual.
- **`--color-accent`'s reserved-use count drops from seven to five (2026-09-18, seventh owner review, UAT gap 38):** the owner asked turn indicators to "stand out nicely without being a firework color." The active-player hand-container ring/glow and the own-hand "Your turn" state accent (both previously `--color-accent`/gold, D-02) move to a new dedicated `--color-turn` token (`#9B65F7`, a deeper/more saturated violet than `--color-suit-rainbow`'s pale `#C9A8FF` lavender — same ~262° hue family, pulled from ~83% down to ~68% lightness, so a Rainbow tile and a turn ring can never be confused). Verified WCAG AA (>=4.5:1) against `--color-bg` and `--color-surface` in `suit-visuals.test.ts`. `globals.css`'s header comment documents the two moved uses; `--color-accent` keeps its remaining five (primary CTA fill, room-code text, own-seat ring, the placeholder-game active-turn indicator, focus rings). Gap 37's new turn sign (below) uses the same `--color-turn` for "Your turn!".
- **New turn sign, below the discard/token column (2026-09-18, seventh owner review, UAT gap 37):** the owner noted free space below the discard and token area and asked for a sign reading "{name}'s turn" / "Your turn!" there, live-region-announced on every turn change, silent once the game ends. Added within the board's existing fixed geometry — no growth, no reflow — sourced from the same seat display-name data the hand panels already use.

Exceptions:
- `--size-touch-min: 44px` (inherited) — every clickable control, **including the keep-hints toggle, the tile-colour swatch buttons, and any discard-pile drag handle**, uses a 44×44px minimum click target via the project's established out-of-flow inset-span pattern (visible glyph stays small; the invisible hit area is 44px). - **Removed this phase (frees height, not a new exception):** the fixed 28px `MarksZone` pip band above every card (own-hand and teammate alike) is deleted per HINT-04. This is the single largest source of freed vertical space this phase spends elsewhere.

## Color

Palette: dark "fireworks night" (unchanged base, Phase 1 D-16). Most of this phase's visual need (hint tint, wooden texture, tile-colour palette) is satisfied by existing tokens or by tokens computed at render time via CSS functions (`color-mix`, opacity layering) from existing tokens. `globals.css`'s no-hex-outside-`@theme` rule is unconditional — its one prior exception (`.table-backdrop`'s scrim) is only an existing token's exact value at partial opacity, introducing no new colour, and is not a precedent for a genuinely new colour. This phase therefore **adds seven new named `@theme` tokens** (five tile-colour presets, one token-art disc/rim pair, one tile drop-shadow) — see the token table below — each documented in `globals.css`'s header in the same style as the existing `--color-accent`/scrim notes, explicitly scoped to decorative/token-art fills, never part of the accent/suit/destructive semantic set. `--color-accent` keeps its exact 7 documented uses; this phase adds **zero** new accent uses (the keep-hints toggle, tile-colour picker, and token art are deliberately styled with `--color-border`/`--color-text-muted`/`--color-card-glow`/`--color-suit-*`/the new tokens below, never accent, to avoid an 8th reserved use).

This is a **location change only**: which colour renders where is unchanged from the original draft; every value above is now a named `@theme` token instead of an inline literal, consumed the same way (`var(--color-tile-preset-warm-sand)`, etc.) wherever the sections below reference these fills.

**HINT-01 colour highlight (D-02, D-04) — REBUILT 2026-09-18 (sixth review, UAT gaps 32/33), superseding the "translucent wash" description below:** a colour clue highlights the touched tile with a thin (3px) inset ring drawn in that suit's own `--color-suit-*` hue (`boxShadow: inset 0 0 0 3px var(--color-suit-{suit})`) — never a fill across the tile face, and never the shared yellow `--color-card-glow`. Per D-04, colour is never the sole carrier: the same ringed tile also shows the suit's own `SuitGlyph` silhouette (A3, RESEARCH.md) rendered faintly (`opacity: 0.35`) in the top-left corner as the non-colour marker, reusing the exact silhouette that already carries suit identity everywhere else in the app, so a grayscale check still reveals which colour was clued by shape alone.

*Original translucent-wash description, superseded:* the first draft tinted the whole tile face (`background: color-mix(in srgb, var(--color-suit-{suit}) 22%, var(--color-surface))`). The owner rejected this outright ("The card is also getting a semi-transparent color shade over the top of the right color shade... remove that") — see gap 33 above.

**HINT-02 number-clue numeral (D-03) — kept as-is, per the owner ("The number hint is ok, keep as-is"):** the touched number renders as a Label-role numeral on the tile back, in `--color-text` on a small `--color-surface` chip inset in the bottom-right corner of the tile back.

**D-06 composition — OVERTURNED 2026-09-18 (sixth review, UAT gap 34).** The original description below ("independent, non-overlapping visual channels... both can be present at once") is no longer how this works. A card's hint display now reflects ONLY its single most recent clue: whichever of {colour ring + glyph, number numeral} that latest clue's own type produces, and nothing from any earlier clue. Telling a card "2" after it was earlier told "blue" now shows the 2 alone — the colour ring and glyph are gone, not layered underneath. `hanabi-hint-logic.ts`'s `hintDisplayFor` reads only the last entry of `facts.positiveClues` (chronological append order) rather than folding over the whole array. A single clue is still exactly one type, so within one clue nothing was lost — only cross-clue accumulation was removed.

*Original composition description, superseded (kept for record only):* "a colour hint and a number hint on the same tile compose as independent, non-overlapping visual channels — colour tint spans the whole tile face; the suit-glyph marker sits in the top-left corner; the number-clue numeral sits in the bottom-right corner... both can be present at once."

**Wooden board texture (D-11, D-15) — owner-overruled 2026-09-17, see the revisions note at the top of this document:** the CSS-generated layered-gradient grain lines described in the original draft were rejected by the owner ("don't generate the texture either — find something free online that looks good, looks board game-y") and replaced via D-11's own documented image-fallback escape hatch. ## Layout — Height Budget (the explicit ledger RESEARCH.md Pitfall 1 requires)

**Owner-overruled 2026-09-17 (see the revisions note at the top of this document):** the side-by-side "LEFT COLUMN (Play/Deck/Discard) beside RIGHT COLUMN (tokens)" model this section originally described was shown to the owner and rejected in favor of the owner's own literal layout — Play at the TOP, the deck count in the MIDDLE, Discard at the BOTTOM (stacked vertically, not side-by-side), with the clue/fuse token column to the RIGHT of that whole stack. Every constant below is quoted from `apps/web/lib/layout-budget.ts`, the single source of truth this file's own header comment requires ("the ledger holds measured numbers, not guessed ones — if the render disagrees with the ledger, the ledger is corrected to the render, never the reverse") — read that file's header for the full correction history (06.2-14 through 06.2-19) rather than treating the numbers below as independently authored.

Extends Phase 6/6.1's fixed three-band desktop layout — 1280×720 is now the **minimum** supported size (`VIEWPORT_TEST_WIDTH_PX`/`VIEWPORT_TEST_HEIGHT_PX`), not the design target (UAT gap 11, overruling the original "no-scroll target" framing) — the board scales up via CSS `zoom` on larger viewports (`apps/web/lib/board-zoom.ts`'s `computeBoardZoom`, capped at 1.8x). The board's primary visual focal point is unchanged by this redesign: the active player's hand-container ring/glow and turn indicator (Phase 6 Active-Player Indication, D-02) remain the single brightest, highest-contrast piece of chrome on screen.

**The binding rule (06.2-15/06.2-19):** every board region — Play, Deck counter, Discard, Tokens — reserves a FIXED height and width up front; content fills that reservation rather than the reservation being derived from whatever content happens to be present. This is what UAT gap 1's fixed-geometry proof (`e2e/start-game.spec.ts`, "UAT gap 1 fixed geometry") checks mechanically: the board's rendered box does not change as tiles accumulate.

- **Number hint (HINT-02):** numeral stamped on the tile back, per Color/Typography § above (unchanged, per the owner).
- **Composition (HINT-04, D-06) — OVERTURNED 2026-09-18 (gap 34):** a card shows only its MOST RECENT clue's own channel — colour and number hints from two DIFFERENT clues no longer coexist on one tile. See Color § D-06 composition above for the full overturn.
- **Lifetime (HINT-03, gap 35):** this hint overlay is the tile's ONLY clue-driven visual — the Phase 6 luminosity frame that used to sit underneath it is deleted, so there is nothing else to govern.
- **Applies to:** own-hand tiles (via `facts` only — same D-15 identity boundary as everything else) and teammate tiles (via `facts` + the teammate's own already-visible suit/rank, matching Phase 6's existing "teammates see their own facts too" precedent).

## Hand Interaction

### Drag shift-aside (DRAG-01, D-08)

During a drag reorder, every other tile in the hand animates its position to open a gap at the current drop index — an extension of the existing `useHandDrag.ts`/`hanabi-drag-logic.ts` pointer-tracked `dragState`, not a new drag paradigm (RESEARCH.md "Don't Hand-Roll" — no HTML5 DnD, no drag library). Motion: `transform` transition on the non-dragged tiles (`transition: transform 150ms ease-out`, reusing the existing `.drag-snap` class's timing/easing from `globals.css`), paired with a `prefers-reduced-motion` static end-state (tiles jump directly to their shifted position with no animated transition, signal — the gap — still visible).

### Always-visible note box (NOTE-03, D-09/D-10)

Replaces `NoteChip.tsx`'s click-to-reveal pencil icon. A **20px-tall** box sits directly above each own-hand tile (reusing 06.1's existing note-row budget, per the Height Budget table above), with:
- **Resting state:** barely-visible `--color-border` outline (1px), transparent/`--color-surface`-at-low-opacity fill, no placeholder text shown unless focused.
- **Hover state:** outline brightens slightly toward `--color-text-muted` (a discoverability cue that this is clickable), no layout shift.
- **Focus/editing state:** `--color-accent` outline (reuses the existing reserved "focus rings on interactive controls" use, same as 06.1's `NoteChip` focus state — not an 8th accent use), placeholder text `"Note…"` shown only while empty and focused.
- **Autosave:** debounced write to `hanabi-notes.ts` storage on every change (not only on Enter/blur) — per D-09, the box is always live, so autosave must not wait for an explicit commit gesture.
- **Character cap:** reconsidered from 06.1's 20-character chip cap since the box is now always visible and inviting longer text — set to **40 characters**, sized to the tile's width without truncation/ellipsis (a wider box than the old chip, but still within the 20px height budget via a small font and single line, no wrap).
- **Privacy:** unchanged from `hanabi-notes.ts` — browser-local, keyed by card id, never rendered on a teammate's tile, never sent to the server.
- **Touch target:** the 20px visible box is padded with an out-of-flow inset span to reach 44px, matching the project's established pattern.

## Shared Discard Order (DISC-01)

Client presentation only — the server-authoritative mechanics (new `reorderDiscard` action, `HanabiState.discardOrder`, `HanabiViewSchema` field) are fully specified in 06.2-RESEARCH.md Pattern 2 and are not a design-contract concern beyond the following UI requirements:

- The Discard area (Board Layout § above) renders every discarded tile in `HanabiView.discardOrder`'s exact order — identical on every player's screen.
- Any seated player can pointer-drag any tile within the discard area to a new position, using the same pointer-event drag architecture as hand reorder (`useHandDrag.ts`/`hanabi-drag-logic.ts` pattern, mirrored into a new `hanabi-discard-drag-logic.ts` per RESEARCH.md), dispatched through the same `act()` chokepoint as every other action.
- **Optimistic order + reconciliation:** while a drag is in flight, the dragging player's own view shows the pending order immediately; a stale rejection (another discard landed mid-drag) silently reconciles to the server's confirmed `discardOrder` on the next frame — no error toast, no confirmation dialog (D-27, last-write-wins).
- **No per-seat ownership affordance:** unlike own-hand reorder, every seated player's pointer can drag every tile in the discard area — there is no "this isn't your tile" disabled state, since D-25 makes this a shared workspace by design.
- Visual treatment of an individual discarded tile matches the existing discard-entry sizing/art (suit glyph + tile-back styling per 06.1), unchanged by this phase except for the new drag affordance and the shared ordering.
- **Group-by-suit (added 06.2-18, not in the original draft):** a `discard-group-by-suit` control re-sorts the shared pile by suit for every player, through the exact same `reorderDiscard` server action a manual drag uses (`groupedBySuitOrder`, a permutation-preserving sort keyed off `game.stacks`' own suit order so Rainbow/Black variants sort correctly with no hardcoded suit list) — **explicitly not a local, per-viewer sort toggle.** Clicking it changes `discardOrder` for every seated player at once, the same as a drag would, and dragging still works normally afterward.
