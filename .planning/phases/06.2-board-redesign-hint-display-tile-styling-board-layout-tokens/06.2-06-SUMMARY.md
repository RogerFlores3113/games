## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `hintsVisible` prop type widened from boolean to ReadonlySet<string>**
- **Found during:** Task 3
- **Issue:** `OwnHandProps`/`TeammateHandProps.hintsVisible` was a single boolean applied uniformly to every card in the hand (06.2-04 placeholder). `hintsVisibleForCard` computes visibility per card id, and the plan's own text says to "pass the resulting set" down to `OwnHand`/`TeammateHand` — a boolean cannot carry that.
- **Fix:** Changed both interfaces' `hintsVisible?: boolean` to `hintsVisible?: ReadonlySet<string>`; each card's own render call now does `hintsVisible ? hintsVisible.has(card.id) : true` (undefined still means "not yet wired, show everything," matching the old default).
- **Files modified:** `apps/web/components/hanabi/Hand.tsx`, `apps/web/lib/own-hand-render.test.ts` (updated the one existing fixture that passed a literal `true`)
- **Verification:** `npx vitest run --project web` (378 tests) and `npx tsc -b apps/web` both green
- **Committed in:** `803c962` (Task 3 commit)

**2. [Rule 3 - Blocking] Fixed stale `note-chip-slot-1` testid references in e2e specs**
- **Found during:** Task 3 verification (`npx playwright test e2e/start-game.spec.ts`)
- **Issue:** Task 1 deleted `NoteChip` and its `note-chip-slot-N` testid, but two e2e specs (`e2e/start-game.spec.ts`'s UI-11 test, `e2e/hanabi-table-polish.spec.ts`'s NOTE test) still referenced the old testid and the old click-to-reveal interaction (click chip -> type in a separate input -> press Enter), which no longer exists on the always-present `NoteBox`.

- **Files modified:** `e2e/start-game.spec.ts`, `e2e/hanabi-table-polish.spec.ts`

## Issues Encountered

**Pre-existing UI-11 viewport overflow, confirmed out of scope.** `e2e/start-game.spec.ts`'s UI-11 test fails: `document.documentElement.scrollHeight` (725px) exceeds `window.innerHeight` (720px) by 5px with five seated players. Investigated by removing every Task 3 addition (keep-hints toggle, TileColorPicker, their wrapper) from `HanabiBoard.tsx` and re-measuring — the numbers were byte-identical (controls-row bottom=722, scrollHeight=725) with only Tasks 1-2 (NoteBox) applied, proving this plan's work is not the cause. The bottom controls row already wraps to several lines at 1280px width before this plan touches it; the overflow traces back to 06.2-04/06.2-05's layout-budget math. Documented in `.planning/phases/06.2-board-redesign-hint-display-tile-styling-board-layout-tokens/deferred-items.md` with a recommendation that 06.2-07 (the board-layout plan that owns these constants) re-measure and fix it as part of its own verification.
