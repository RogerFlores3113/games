Create `apps/worker/src/room-do.ts` exporting `class RoomDO extends Server<Env>` from `partyserver`, with `static options = { hibernate: true }`.

Hold two in-memory fields, both reconstructable and neither persisted: `room: RoomState | null` (rehydrated in `onStart`) and `bindings: SeatBindings` (the seat→connection-id map from Plan 05). Persist nothing else in memory — RESEARCH's anti-pattern list is explicit that memory is wiped on eviction.

`onStart()` — call `loadRoom(this.ctx.storage, () => createEmptyRoom(this.name as RoomCode, "base", Date.now()))`. `this.name` is the room code `partyserver` routed on. Then recompute timers with `computeRoomTimers(room, Date.now())` and call `this.#syncAlarm(timers)`. `#syncAlarm` reads the CURRENT pending alarm via `ctx.storage.getAlarm()` and only calls `setAlarm(next)` when `next !== null && next !== currentAlarm`, deleting the alarm when `next === null`. This guard is what prevents Pitfall 2 — an unconditional `setAlarm` on every hibernation wake perpetually defers the deadline so it never fires. Add that sentence as a comment on `#syncAlarm`, because it is the single most deletable-looking safety line in the file.

`onConnect(connection, ctx)` — do NOT assign a seat here. Read the `Origin` header and, if present and not matching an allowlist of the production web origin plus `localhost` dev origins, close the connection (Pitfall 7 / T-1-05 — browsers do not CORS-gate WebSocket handshakes, so this is server-side or nowhere). Otherwise leave the connection unseated and wait for an explicit `join` message; making join an explicit message rather than URL query parsing means the same validated code path serves first join and reconnect, which is what RT-05 requires in Phase 5.

`onMessage(connection, raw)` — the single dispatch point. Steps, in order: (1) `parseClientMessage(String(raw))`; on `{ok:false}` reply `error`/`bad_request` and return. (2) For `join`: call `resolveSeatByToken(room.seats, msg.seatToken)`; on a hit, call `markConnected` and take the reclaim path; otherwise call `joinRoom(...)` with `mintSeatId`/`mintSeatToken` injected from `seat-identity.ts`. On a refusal, send `{type:"refused", reason}` and close the socket — a refused arrival (D-06 full, D-14 in-progress) receives a reason and nothing else. On success, call `rebindSeatConnection`; if it returns a `supersededConnectionId`, send `{type:"superseded"}` to that connection and close it with `SUPERSEDED_CLOSE_CODE` (D-08). Then send `{type:"joined", seatId, seatToken, view}` to THIS connection only — the only message that ever carries a seat token — and push state to everyone else. (3) For `set_variant` / `start_game` / `game_action` / `leave`: resolve the actor's seat id from `bindings` (never from the message body — that is the T-1-04 boundary), call the corresponding `room-state.ts` function, send `{type:"error", code}` on refusal, and broadcast on success.

`#pushState()` — the ONLY outbound path. Iterate `this.getConnections()`; for each, look up its seat id from `bindings`; skip unseated connections; and send `encodeServerMessage({type:"state", view: toSeatView(this.room, seatId)})`. Because `toSeatView` is called once per connection with that connection's own seat id, there is no shared payload to leak. Add a comment: no other method in this class may call `connection.send` with a payload it did not obtain from `toSeatView` — Phase 2's HIDE-02 audit reads this file.

`onClose(connection, code, reason, wasClean)` — resolve the seat from `bindings`, drop the binding, call `markConnected(room, seatId, false, now)`, persist, push state to remaining connections (this is what makes ROOM-04's disconnected indicator live), and re-sync the alarm — a disconnect is what arms the D-07 host-transfer and D-12 seat-release deadlines.

`onError` — log and close; never rethrow, since an exception escaping a handler tears down the room for every seat.

After every state mutation call `saveRoom(this.ctx.storage, room, computeRoomTimers(room, now))` and then `#syncAlarm`. Factor that trio into one private `#commit(now)` method so no call site can forget one of the three.

Rewrite `apps/worker/src/index.ts` to export `RoomDO` and a default fetch handler returning `(await routePartykitRequest(request, env)) ?? new Response("Not Found", {status: 404})`. Keep the Plan 01 smoke sentinels exported so the Wave 0 bundle grep and E2E smoke spec continue to pass. Update `wrangler.jsonc` only if the binding name must change — it should not; `ROOM` / `RoomDO` / `new_sqlite_classes` were set correctly in Plan 01.

  <action>
Add `async onAlarm()` to `RoomDO` as the single entry point for all three timer types.

It must: (1) ensure `this.room` is loaded (an alarm wake re-runs the constructor, so state may be cold); (2) call `dueTimers(loadTimers(...), Date.now())`; (3) process EVERY due event, not just the earliest — several deadlines can coincide within one alarm firing, and processing only the head is the second way Pitfall 1 manifests; (4) recompute timers and `#syncAlarm` at the end.

Per event type:
- `host_transfer` → `transferHost(room, now)`, then push state so every client sees the new host badge.
- `seat_release` → `releaseSeat(room, seatId, now)` (lobby only, already guaranteed by `computeRoomTimers`), then push state so remaining players see the seat vanish.
- `idle_gc` → the room is abandoned. Close every remaining connection, call `this.ctx.storage.deleteAll()`, set `this.room = null`, and return WITHOUT rescheduling — a deleted room must not keep waking itself up. This is ROOM-08: after this returns, the Durable Object holds zero storage and will hibernate away; a later visitor to the same code gets a fresh empty lobby, which is the correct outcome for an abandoned room.

Guard the whole handler in a try/catch that logs and still calls `#syncAlarm` on failure, so one bad event cannot permanently disarm a room's GC.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → Worker fetch handler | Anyone can open a WebSocket to any room code; browsers do NOT apply CORS to the WS handshake |
| WebSocket frame → `onMessage` | Every frame is attacker-controlled bytes |
| connection identity → seat identity | `bindings` is the ONLY mapping from a socket to a seat; the message body never supplies one |
| room state → each socket | `#pushState` is the single crossing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-03 | Tampering | `onMessage` | mitigate | Every frame goes through `parseClientMessage` (closed strict Zod union, non-throwing) before dispatch; anything else yields an `error` reply. Integration-tested with malformed JSON, unknown types, and extra keys, asserting the socket survives (ASVS V5). |
| T-1-04 | Elevation of Privilege | `set_variant` / `start_game` / `game_action` | mitigate | The actor's seat id is resolved from the server-side `bindings` map, never from the message body — the wire schema has no `seatId` field to supply. Host checks happen in `room-state.ts` against persisted `hostSeatId`. |
| T-1-01 | Spoofing | `join` with a seat token | mitigate | `resolveSeatByToken` requires exact 24-char equality against a server-minted token. A fabricated token yields a NEW seat, never an existing one — integration-tested explicitly (RT-07). |
| T-1-02 | Tampering | second-tab rebinding | mitigate | `rebindSeatConnection` swaps only the in-memory connection map; the superseded socket gets `{type:"superseded"}` then close 4001, so a stale tab is told rather than left half-alive corrupting state (D-08). |
| T-1-05 | Information Disclosure | cross-origin WebSocket | mitigate | `onConnect` validates the `Origin` header against an allowlist (production web origin + localhost dev), because the browser will not. Defense in depth for the stated friend-group threat model; a determined non-browser client can forge `Origin`, which is accepted — per-seat projection, not origin checking, is the real confidentiality control. |
| T-1-11 | Information Disclosure | outbound sends | mitigate | Exactly one `toSeatView(` call site, inside `#pushState`, called once per connection with that connection's own seat id; `this.broadcast(` is grep-forbidden. Integration test asserts raw received bytes never contain another seat's token. |
| T-1-10 | Denial of Service | handler exceptions | mitigate | `onError` never rethrows; `onAlarm` is try/caught and still re-syncs the alarm on failure, so one bad event cannot permanently disarm a room's GC. |
| T-1-19 | Denial of Service | abandoned rooms | mitigate | `idle_gc` calls `ctx.storage.deleteAll()` and stops rescheduling (ROOM-08), bounding storage against the 5GB Free-plan cap. |
| T-1-22 | Denial of Service | unauthenticated room creation | accept | Any code can be dialled and will lazily instantiate a Durable Object. Idle GC reaps an empty lobby after 1 hour, and the Free plan's 100k req/day cap is the practical backstop for a friend-group app. Rate limiting is not built in this phase; revisit if the domain is ever shared publicly. |
</threat_model>
