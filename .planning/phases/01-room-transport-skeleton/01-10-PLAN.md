<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a room-link holder → an occupied seat | The RT-07 adversary: someone with the shareable code but not the seat token |
| browser localStorage → the server | The spec deliberately forges this input to prove the server does not trust it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Spoofing | seat takeover via forged token | mitigate | `seat-takeover.spec.ts` injects a fabricated 24-character token into `localStorage` before load and asserts the resulting seat is never the victim's. This is the end-to-end verification of the RT-07 control implemented in Plan 05 and wired in Plan 07 — an executable adversary, not a code review. |
| T-1-02 | Tampering | second-tab supersession | mitigate | The spec asserts the seat count is unchanged after supersession, which is the precise statement of "Phase 1 only needs this to not corrupt seat state" (D-08). |
| T-1-11 | Information Disclosure | refusal screens | mitigate | Asserts `seat-list`, `counter-value` and `start-game` have DOM count 0 on both refusal screens — a refused visitor learns the reason and nothing about who is in the room or what is happening. |
| T-1-04 | Elevation of Privilege | non-host controls | mitigate | Asserts the joiner has no variant control and that the variant control disappears after start (ROOM-05 lock). Server-side authorisation is separately proven in Plans 04 and 07; this covers the surface. |
| T-1-28 | Denial of Service | flaky/hanging E2E suite | mitigate | No `waitForTimeout` anywhere (grep-asserted), `retries: 0`, bounded per-assertion timeouts, and both dev servers managed by Playwright's `webServer`. A suite that hangs or flakes stops being run, which silently removes this entire threat register from enforcement. |
</threat_model>
