# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind v4 components. Phase 1's surface area (two forms, a seat list, one refusal card, one counter button) is small enough that hand-rolled components cost less than adopting and reskinning a full primitive library against a bespoke dark "fireworks night" palette. Revisit for Phase 6 if the card-table UI's interactive surface (tooltips, popovers for clue selection) grows enough to justify Radix primitives. |
| Icon library | `lucide-react` — tree-shakeable SVG React components, zero CSS-in-JS runtime (compliant with `CLAUDE.md`'s "What NOT to Use" table), pairs cleanly with Tailwind utility classes for stroke/color/size |
| Font | `Geist` (UI text) + `Geist Mono` (room code only) via `next/font/google`. Next.js's own font, zero extra vendor dependency, ships as a variable font with no layout-shift/FOUT risk under `next/font`. Geist Mono is reserved specifically for the room code — monospaced characters make a spoken-then-typed code easier to scan for transcription errors, on top of D-01's already-disambiguated alphabet. |

**shadcn gate note (autonomous run):** `components.json` was not found and this is a greenfield Next.js repo, so the shadcn initialization gate would normally prompt: "Initialize shadcn now? [Y/n]." That flow requires an interactive step (visiting ui.shadcn.com/create and pasting back a preset string) that cannot be completed inside this autonomous pipeline run. Resolution: proceed with `Tool: none` for Phase 1 as documented above. **Flag for developer review:** if a component library is wanted later (e.g., before Phase 6's denser interactive surface), run `/gsd:ui-phase` interactively to complete the shadcn preset step, rather than defaulting it here.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inline padding (e.g. connection-status dot to name) |
| sm | 8px | Compact element spacing (seat row internal padding, form field label-to-input gap) |
| md | 16px | Default element spacing (form field stacking, card internal padding) |
| lg | 24px | Section padding (lobby panel padding, refusal-card padding) |
| xl | 32px | Layout gaps (space between room-code block and seat list) |
| 2xl | 48px | Major section breaks (space above/below the room-code display) |
| 3xl | 64px | Page-level spacing (vertical centering offset on create/join/refusal screens) |

Exceptions: Icon-only buttons (copy-link icon button) use a 44×44px minimum touch/click target regardless of their visible icon size, per standard accessible-target-size practice — the icon itself renders at 20px inside that target.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.5 |
| Heading | 24px | 600 (semibold) | 1.2 |
| Display (room code only) | 40px | 600 (semibold) | 1.2 |

Only two weights exist in this phase: 400 (regular, `Geist`) and 600 (semibold, `Geist` for headings/labels, `Geist Mono` for the Display role). Do not introduce a third weight or a third typeface.

**Display role usage:** reserved exclusively for the room code (`ABC123`) on the lobby and any share affordance. Rendered in `Geist Mono`, `40px`, letter-spaced (`tracking-wide` / ~0.05em) so it reads cleanly both on-screen and when read aloud digit-by-digit over a voice call — this is the "speakable" requirement from CONTEXT.md's `<specifics>`, and it is the one piece of typography in this phase that is explicitly NOT decorative.

## Color

Palette: dark "fireworks night" (D-16). Values below are the CSS custom properties Phase 1 defines via Tailwind v4's `@theme` block in `apps/web/app/globals.css`. Phase 6 inherits these tokens rather than redefining them — do not hardcode hex values outside this token set once implemented.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0F1A` (`--color-bg`) | Page background on every screen — near-black navy, the "night sky" |
| Secondary (30%) | `#141A2E` (`--color-surface`) | Lobby panel, seat-list rows, form cards, refusal-screen card |
| Accent (10%) | `#F5B942` (`--color-accent`) | **Reserved for:** primary CTA buttons ("Create room", "Join room", "Start game"), the room-code Display text, the "you are here" ring around the current player's own seat row, the active-turn indicator in the placeholder counter game, focus rings on interactive elements. Nothing else uses this color — this is the one "firework spark" in an otherwise dark, quiet frame. |
| Destructive | `#F0453D` (`--color-destructive`) | Refusal-screen icon/accent border ("room full", "game in progress") only. No delete/kick/leave-with-confirmation action exists in Phase 1 (see Copywriting Contract), so this token has exactly one use site this phase. |

**Supplemental tokens** (not part of the required 60/30/10 split, but needed to implement the above and established here for Phase 6 to inherit):

| Token | Value | Usage |
|-------|-------|-------|
| `--color-text` | `#F4F6FB` | Primary text on dark surfaces (body, headings) |
| `--color-text-muted` | `#8B93A8` | Secondary/label text, placeholder text, seat-list metadata |
| `--color-border` | `#232B45` | Hairline borders/dividers between seat rows and around cards |
| `--color-status-connected` | `#34D399` | Connection-status dot — **always paired with the text label "Connected", never color alone** (see Accessibility note below) |
| `--color-status-disconnected` | `#6B7280` (slate, not destructive red) | Connection-status dot — **always paired with the text label "Disconnected"**. Deliberately not the destructive-red token: a disconnected teammate is an expected, non-error state (someone's wifi dropped), not a failure needing alarm-red |

**Accent reserved for (explicit list, repeated for clarity):** primary CTA button fill, room-code Display text, own-seat "you" ring, active-turn indicator (counter game), focus rings. No other element — not links, not secondary buttons, not icons — uses the accent color.

**Accessibility forward-compatibility note (for Phase 6):** every status/state signal in this phase pairs color with a text label or distinct shape (dot presence + word, never hue alone). This convention is deliberate groundwork for Phase 6/7's colorblind-safe requirement (UI-06, UI-07) — luminosity- and glyph-based signaling there will extend this same "never color-alone" rule rather than introducing it for the first time under harder constraints.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — create room | "Create room" |
| Primary CTA — join room | "Join room" |
| Primary CTA — start game (host only) | "Start game" |
| Secondary — copy link | "Copy link" → on click, button label swaps to "Copied!" for ~2s, then reverts |
| Empty state heading (lobby, before 2 players seated) | "Waiting for players" |
| Empty state body | "Share the room code above — you need 2 to 5 players to start." |
| Refusal — room full (D-06) heading | "This room is full" |
| Refusal — room full body | "All 5 seats are taken. Ask the host to open a new room." |
| Refusal — game in progress (D-14) heading | "This game is already in progress" |
| Refusal — game in progress body | "You can't join mid-game. Ask the host for a new room, or wait for this one to finish." |
| Superseded-tab notice (D-08) | "This room was opened in another tab." (shown in place of the game UI on the stale tab; no other action offered) |
| Duplicate-name display (D-09, auto-suffix) | `{Name} (2)`, `{Name} (3)`, etc. — silent, no user-facing message, purely a seat-list rendering rule |
| Variant picker label | "Variant" with three options: "Base", "Rainbow", "Black" |
| Destructive confirmation | **None in Phase 1's scope.** There is no delete-room, kick-player, or "leave game" action requiring confirmation this phase — leaving the lobby (closing the tab) silently frees the seat per D-12, with no confirmation dialog. The `--color-destructive` token exists solely for the refusal-screen accent, not for a confirmable destructive action. |

## Screens & States (Phase 1 scope)

Supplemental to the template's core contract — describes how the tokens above apply to each of Phase 1's five screens, per the `<scope>` block this spec was generated against.

1. **Create-room screen** (D-03) — single screen, centered card on `--color-bg`. Display-name text input, variant picker (Base/Rainbow/Black, three equal-weight options, no default pre-selected bias implied beyond Base being first), "Create room" primary CTA (accent fill). No intermediate share screen — submitting routes directly into the lobby, already seated as host.
2. **Join screen** (`/room/ABC123` without a seat token) — same visual shell as create-room (centered card), room code shown in Display typography above the form so the joining player can confirm they're entering the right room before typing their name. Display-name input + "Join room" CTA. No variant picker (locked by host).
3. **Lobby** — full-width panel on `--color-surface`. Room code in Display role at the top with an adjacent "Copy link" button. Seat list below: each row shows display name (auto-suffixed per D-09), a connection-status dot + label (`--color-status-connected` / `--color-status-disconnected`, always with text), and a host badge on the current host's row. The current viewer's own row carries the accent "you" ring. Host-only: variant picker (editable until start, D-13) and "Start game" CTA, disabled/inert until 2–5 seats are filled — no separate error message needed for the disabled state; the disabled button plus a small `--color-text-muted` caption ("Need 2–5 players") communicates why.
4. **Refusal screen** — one shared component for both "room full" (D-06) and "game in progress" (D-14): centered card, `--color-destructive` icon/border accent, heading + body per the Copywriting Contract, no CTA back into the room (nothing to retry into). Structurally identical markup/props for both cases; only the heading/body copy and an internal `reason: "full" | "in-progress"` prop differ — this is the shared-shape requirement from CONTEXT.md's `<specifics>`.
5. **Placeholder counter game** (D-15) — deliberately minimal: a single large number (reuse the Display typography role, `--color-text`, not accent, to keep it visually distinct from the room code), a turn indicator ("Your turn" / "Waiting for {name}", accent-colored only for the active player's own view), and a single "+1" button (accent fill, disabled for non-active players). No card art, no board chrome — this screen exists to prove turn order and broadcast, not to look finished, and its minimalism is intentional so its Phase 2 deletion is a small, legible diff (per the `<specifics>` note in CONTEXT.md).

## Component Notes

- **Seat row** is the one component reused across the lobby and (implicitly) later phases — build it now as a small, isolated component (`SeatRow`) taking `{name, connected, isHost, isSelf}` props, since Phase 6's in-game player list is a near-identical shape.
- **RefusalCard** should be built as the single shared component described above, parametrized by a `reason` prop — do not create two separate components for "full" vs "in-progress".
- **Buttons**: exactly two visual variants needed this phase — primary (accent fill, `--color-text` on top for contrast) and a plain/ghost variant for "Copy link" (border `--color-border`, `--color-text` label, no fill). Do not introduce a third button variant in Phase 1.
- Use `clsx` for conditional class composition (own-seat ring, disabled button states, connection-status dot color) per `CLAUDE.md`'s locked stack — no `tailwind-merge` needed at this phase's component complexity.
