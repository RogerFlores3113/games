Create `apps/worker/src/room-state.ts` as pure functions taking a `RoomState` and returning a new `RoomState` — no `this`, no `ctx.storage`, no WebSocket, no `Date.now()` reads (every function that needs a timestamp takes `now: number` as a parameter, so tests are deterministic and Plan 06's alarm tests can drive time freely).

Export:

- `createEmptyRoom(code, variant, now): RoomState` — status `"lobby"`, empty `seats`, `hostSeatId: null`, `adapterId: counterGame.id`, `game: null`, `createdAt`/`lastActivityAt` set to `now`.
- `joinRoom(state, input: { displayName, seatToken?, now, mintSeatId, mintSeatToken }): JoinResult` — a discriminated result `{ ok: true; state; seatId; seatToken; wasReclaim: boolean } | { ok: false; reason: RefusalReason }`. Order of checks, which is load-bearing: (1) if `seatToken` is present and matches a persisted seat, this is a RECLAIM — mark that seat connected, return `wasReclaim: true`, and permit it regardless of room status, because RT-03/RT-04 in later phases depend on reclaim working mid-game; (2) if `seatToken` is present but matches nothing, fall through to a new join (a stale token from a GC'd room must not hard-fail); (3) new joins into a room whose status is not `"lobby"` are refused with `in_progress` (ROOM-07, D-14); (4) new joins when `seats.length >= MAX_PLAYERS` are refused with `full` (ROOM-06's ceiling, D-06); (5) otherwise append a seat at the end (join order, D-12) with `displayLabel` from `deriveDisplayLabel`, and if `hostSeatId` is null, assign host to this first seat (D-03 — the creator lands in the lobby already seated as host). Token minting is injected via `mintSeatId`/`mintSeatToken` callbacks so this module stays free of `nanoid` and tests are deterministic.
- `releaseSeat(state, seatId, now): RoomState` — removes the seat entirely (D-12: leaving the lobby frees the seat). If the departing seat was the host and other seats remain, reassign `hostSeatId` to the earliest-joined remaining seat. This function is called only for lobby seats; Plan 06 owns the grace period that decides when.
- `markConnected(state, seatId, connected, now): RoomState` — flips `Seat.connected`, which is what ROOM-04's live connection-status list renders, and sets `Seat.disconnectedAt` to `now` on disconnect / `null` on reconnect. That field is persisted because Plan 06's host-transfer and seat-release deadlines are derived from it and must survive a hibernation eviction.
- `transferHost(state, now): RoomState` — reassigns `hostSeatId` to the earliest-joined CONNECTED seat (D-07). No-op when the current host is connected or no connected seat exists. Called by Plan 07 when the scheduler reports a due `host_transfer` timer; the policy of when lives in Plan 06, the state change lives here.
- `setVariant(state, actorSeatId, variant): Result<RoomState, RefusalReason>` — refuses `not_host` unless `actorSeatId === state.hostSeatId`, and refuses `bad_request` unless `status === "lobby"` (D-13: the variant locks at start, ROOM-05).
- `startGame(state, actorSeatId, now, seed): Result<RoomState, RefusalReason>` — refuses `not_host` for a non-host; refuses `bad_request` unless `status === "lobby"` and `seats.length` is between `MIN_PLAYERS` and `MAX_PLAYERS` inclusive. On success sets `status: "in_progress"` and `game: adapter.createInitialState({ seatIds, variant, seed })`. There is deliberately NO ready-state check anywhere in this function or in `RoomState` (D-10, D-11) — if you find yourself adding a `ready` field, stop; it was cut from scope.
- `applyGameAction(state, actorSeatId, request, now): Result<RoomState, RefusalReason>` — refuses `bad_request` unless status is `"in_progress"`, then delegates to `adapter.applyAction(state.game, actorSeatId, request)`, mapping the adapter's `AdapterError` onto a `RefusalReason`. Then calls `adapter.checkGameEnd`; a non-null result sets `status: "ended"`. This function must not inspect the contents of `request` or of `state.game` — that is the FDN-01 line.
- `toSeatView(state, seatId): RoomView` — the SINGLE outbound serializer. Builds `PublicSeat[]` from the persisted seats (dropping `seatToken` and `displayName`, keeping `displayLabel`, `connected`, and a computed `isHost`), sets `youSeatId`, and sets `game` to `state.game === null ? null : adapter.toPlayerView(state.game, seatId)`. Add a file-level comment: this is the only function in the worker permitted to convert `RoomState` into anything sent over a socket; Phase 2's redaction contract (HIDE-02) hardens exactly this chokepoint, so no second serializer may be introduced.

The adapter is a module-level constant `const adapter = counterGame` with a comment marking it as the D-15 placeholder that Phase 2 replaces. Do not accept the adapter as a parameter threaded through every function — one swap site is the legible-diff property D-15 was chosen for.

Every mutating function updates `lastActivityAt = now`, since Plan 06's idle GC reads it.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-04 | Elevation of Privilege | `setVariant`, `startGame` | mitigate | Both compare `actorSeatId` against the persisted `hostSeatId` and return `not_host` otherwise. `hostSeatId` is only ever set by `joinRoom`/`releaseSeat`, never from client input. Covered by explicit non-host tests. |
| T-1-13 | Tampering | `setVariant` after start | mitigate | Status guard refuses any variant change once `status !== "lobby"` (ROOM-05 lock, D-13); test asserts the persisted variant is unchanged after the refusal, not merely that an error was returned. |
| T-1-11 | Information Disclosure | refusal results | mitigate | `joinRoom` failure results are `{ok:false, reason}` only — no seats, no code, no status object. A refused arrival (D-06/D-14) learns the refusal reason and nothing else. Asserted by exact-key tests. |
| T-1-14 | Information Disclosure | `toSeatView` | mitigate | `PublicSeat` is built by explicit field construction, not by spreading the persisted seat, so `seatToken` and the raw `displayName` cannot ride along. Asserted by a token-substring scan over the serialized view for every seat. |
| T-1-10 | Denial of Service | `applyGameAction` | mitigate | Delegates to the adapter, which is fuzz-tested in Plan 02 to never throw; `applyGameAction` maps errors to `RefusalReason` rather than propagating. |
