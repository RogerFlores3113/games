  <action>
    Create run/run-actions.ts exporting `applyRunAction(run, actorSeatId, action: RunAction, catalog): AdapterResult<RunState, RunError>`.

    1. Guard order:
       - typeof action !== "object" or null → invalid_action;
       - actor not in seatIds → not_a_seat;
       - runStatus(run) !== "in_progress" → run_over;
       - dispatch on action.type; an unknown type → invalid_action.

    2. Handlers (local functions), all immutable:
       - pick-draft: requires runPhase fireside.
       - set-loadout:
         - requires fireside;
         - gearIds must be an array of strings (else invalid_action);
         - check duplicates, then ownership;
         - build the candidate run with the actor's equippedGearIds replaced;
         - over_capacity if loadoutSize(gearIds) > capacityOf(candidate, actor, catalog);
         - remove the actor from readySeatIds.
       - ready: requires fireside. Check draft_pending, then already_ready. Add the actor, and if every seat is ready, return startAttempt(next, catalog), which itself runs advanceRun.
       - skip-window: requires runPhase pre-deal. If the actor is not in preDealPendingSeatIds → nothing_to_skip. Otherwise append GearUse { kind: "skipped" } for each equipped pre-deal gear of the actor not yet spent.
       - use-gear → applyUseGear.
       - whisper → applyWhisper.
       - pick-objective / play-card:
         - require runPhase camp;
         - result = applyCampAction(attempt.camp, actor, { type, ...id }, rulesFor(run, catalog));
         - on error return it; on ok replace attempt.camp.

    3. After ANY accepted action, return advanceRun(next, catalog). This settles camps decided by a play or by a gear effect (Camouflage removing the last open objective), and deals once pre-deal resolves.

    The header documents:
    - the dispatcher is the Phase 11 entry point;
    - the guard order;
    - D-07: ready is pure data, disconnect pausing belongs to Phase 11, and there is no force-start;
    - D-13: actions are processed strictly in arrival order, with no queue;
    - there is no undo action (GEAR-05, XRULE-08).
  </action>
