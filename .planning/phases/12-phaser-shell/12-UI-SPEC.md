# Phase 12 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Note on scope:** This phase has two visual surfaces with different rules:
1. **HTML chrome** — the corner settings button/modal (D-05) and the existing landing/lobby pages. These MUST reuse the site's existing Tailwind v4 `@theme` tokens (`apps/web/app/globals.css`) byte-for-byte. No new HTML-side tokens are introduced this phase.
2. **The Phaser canvas world** — the 640×360 pixel-art stage (D-09/D-10). Canvas drawing code cannot consume CSS custom properties directly (Phaser takes numeric hex), so this contract defines a small mirrored palette module that is the single source of truth for canvas colors, with the same hex values as the HTML tokens wherever a meaning is shared (turn indicator, destructive, connection status), plus a documented, minimal set of new "world-only" colors for things the HTML palette has no equivalent for (stump wood, jungle backdrop, letterbox).

Every visual decision below is either locked by `12-CONTEXT.md` (D-01…D-17) or is this researcher's resolved default per the `--auto` mode instruction — no open questions are left for the checker to bounce back for a live user answer.

## Spacing Scale

### HTML chrome (settings modal, corner button)

Reuses the existing `--space-*` scale from `apps/web/app/globals.css` unchanged:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exception: the corner settings-gear trigger button uses the project's existing `--size-touch-min: 44px` touch target (already defined in `globals.css`), positioned with `--space-sm` (8px) inset from the canvas container's corner — matching Hanabi's existing icon-button touch-target precedent (`06.1-10`'s discard-toggle inset-span pattern), not a new spacing rule.

### Canvas world (stage-resolution units, 640×360 base)

The 8-point HTML scale does not transfer directly to a 640×360 pixel-art stage (D-10) — spacing here is measured in stage pixels, which are themselves whole-number-scaled (2×/3×/4×) by the browser, so a "4px" stage gap already renders as 8px/12px/16px on screen. Declared stage-pixel gutters:

| Token | Stage px | Usage |
|-------|----------|-------|
| stage-xs | 2px | Card-to-card overlap trim, glyph padding inside a mini-card |
| stage-sm | 4px | Gap between adjacent HUD elements at one seat (gear box to objective marker) |
| stage-md | 8px | Seat-to-seat visual separation around the oval table |
| stage-lg | 16px | Table-to-HUD-edge margin (supplies/camp-number/boss-twist row to stage edge) |

Exception: the 17-card (3-player) hand fan (D-10) uses a variable overlap, not a fixed gutter — see Typography/Motion discretion notes; overlap is computed from hand size, not a static token.

## Typography

### HTML chrome

Reuses the existing site typographic roles exactly (`apps/web/app/globals.css`) — no new HTML text roles this phase:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.5 |
| Heading | 24px | 600 | 1.2 |
| Display | 40px | 600 | 1.2 (reserved for the room code only — unaffected by this phase) |

The settings modal (D-05) is built by porting `SettingsModal.tsx`'s existing structure verbatim (fixed backdrop, centered `role="dialog"`, Escape/backdrop-click close, two-step delete confirm) — it inherits these roles with zero new declarations.

### Canvas world (bitmap pixel font, D-12)

Placeholder-tier for Phase 12 (Phase 14 supplies the final font asset per Research's Open Question 2 — treated as throwaway infrastructure now, same spirit as D-13's flat-shape art). Two sizes only, both measured at stage (1×) resolution:

| Role | Stage px | Usage |
|------|----------|-------|
| world-label | 8px cell height | Seat names, gear box names, supply count, objective marker glyphs — short, frequently-truncated labels |
| world-sign | 12px cell height | The in-world wooden sign's window/state text (D-03) and the boss-twist name (D-15) — the single largest, most important read-at-a-glance text in the scene |

No third canvas text size. Long names are truncated with a trailing ellipsis glyph (per D-12), never wrapped or scaled down further — truncation width is fixed per label slot, not computed per-string.

## Color

### HTML chrome — reuses existing tokens, zero new HTML-side colors this phase

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg` (`#0B0F1A`) | Page/body background — unchanged |
| Secondary (30%) | `--color-surface` (`#141A2E`) | Settings modal panel background |
| Accent (10%) | `--color-accent` (`#F5B942`) | Unchanged reserved list from `globals.css` (primary CTA fill, room-code text, own-seat ring, active-turn indicator, focus rings). This phase adds **zero** new accent uses in HTML — the settings-gear trigger and modal controls use `--color-text`/`--color-border`, not accent, matching `SettingsModal.tsx`'s existing non-accent chrome buttons |
| Destructive | `--color-destructive` (`#F0453D`) | Host-only delete/restart room control inside the settings modal (D-05) — direct reuse of Hanabi's existing two-step confirm pattern, no new copy or mechanism |

Accent reserved for (unchanged, verbatim from `globals.css`): primary CTA fill, the room-code Display text, the own-seat "you are here" ring, the active-turn indicator, and focus rings. **Nothing new is added to this list by Phase 12.**

### Canvas world — mirrored + new world-only tokens

Lives in a single new module, `apps/web/components/expedition/phaser/palette.ts`, the sole source of truth for every hex value the Phaser scenes draw with. Every value that has an HTML-side meaning duplicates that meaning's exact hex (documented with a comment pointing back to `globals.css`, mirroring the codebase's existing precedent for deliberate, documented duplication across a runtime boundary — e.g. `packages/rules/src/expedition/adapter.ts`'s locally-duplicated `Variant` type). Values are plain hex strings for Vitest-testability; call sites convert to Phaser's `0x`-int form at the point of use.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) — world backdrop | `--color-expedition-jungle` `#0F2318` (new) | The stage's base fill behind the table — a dark jungle green, deliberately distinct from Hanabi's night-sky `--color-bg` navy so Expedition reads as its own place, per the spec's roguelite-jungle framing |
| Secondary (30%) — stump/table surface | `--color-expedition-stump` `#4A3420` (new) | The oval stump table, supply crates, gear boxes — a mid-brown wood tone, D-13's "flat shapes plus labels" placeholder fill |
| Accent (10%) — turn/timing-window glow | mirrors `--color-turn` `#9B65F7` | Seats that may act (D-03), usable-gear pulse, the highlight step of D-02's highlight-then-confirm flow. Extends the existing Hanabi precedent (`--color-turn` was split off `--color-accent` specifically so a turn/actionable signal never doubles up with a CTA-gold meaning) rather than inventing a second "your turn" color |
| Destructive / danger | mirrors `--color-destructive` `#F0453D` | Camp-failed state feedback in-canvas (e.g. a failed objective's marker), if this phase's placeholder objective-status rendering needs a failure color — reuses the same red the HTML destructive actions use, one failure-meaning color across the whole app |
| Connected / disconnected | mirrors `--color-status-connected` `#34D399` / `--color-status-disconnected` `#6B7280` | A disconnected teammate's dimmed seat + sleeping icon (D-08) uses the disconnected gray as its tint; no new "asleep" color invented |
| Legal-play highlight vs. dimmed | full-opacity draw vs. 40% alpha multiply on the same sprite | Cards you can't legally play are dimmed (SCENE-03) by alpha reduction on the existing card texture, never a separate "disabled" color swatch — this keeps every card's suit-identifying color intact just less prominent, matching Hanabi's own dimming precedent for disabled controls |
| Letterbox fill | `--color-expedition-letterbox` `#060D08` (new) | The dark jungle-colored fill for leftover space outside the whole-number-scaled 640×360 stage (D-09) — deliberately darker/more desaturated than the jungle backdrop itself so the stage edge is always visually distinguishable from the letterbox |
| Boss-twist placeholder effects (D-15) | Monsoon rain: `#6FA8FF` (mirrors `--color-suit-blue`); Eclipse sky tint: a 50% alpha overlay of `--color-expedition-letterbox`; Thick Fog / Mutiny: no new color, communicated via the wooden sign text only | Reuses existing suit-blue hue for "water/rain" rather than minting a new blue; avoids inventing four bespoke boss palettes for placeholder-tier art that Phase 14 replaces anyway |

Accent reserved for (canvas): the turn/timing-window glow only (mirroring `--color-turn`) and nothing else — canvas code must never draw a CTA-style gold highlight (`--color-accent` itself), since there is no in-canvas call-to-action button; that meaning stays exclusively in the HTML settings modal.

**Contrast note:** the mirrored tokens (`--color-turn`, `--color-destructive`, `--color-status-*`) already carry verified WCAG AA contrast against `--color-bg`/`--color-surface` in `apps/web/lib/suit-visuals.test.ts`. The two new world-only tokens (`jungle`, `stump`, `letterbox`) are backdrop/surface fills, not text-contrast-bearing colors — any text drawn over them uses the mirrored `--color-text` (`#F4F6FB`) equivalent, which is near-white and passes AA against all three new dark fills by inspection (all three are <15% lightness).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | No new CTA copy this phase — Phase 12 *enables* the existing landing-page "Create room" flow for Expedition (MGR-01/D-17); the button label is unchanged, generic across games, per the existing `LandingForm.tsx` |
| In-world window sign (D-03) | Short, imperative, present-tense labels only, matching the examples the context already locked: `"Pick objectives"`, `"Between tricks"`, `"Your turn"`, `"Waiting on {name}"`. Never a full sentence — the sign is a glance-read cue, not an explanation (per the phase's "world-as-interface, minimal text" direction) |
| Empty state | None new — the pre-game lobby (waiting for players / seats open) is shared, game-agnostic code already covering Hanabi and Expedition alike; no Expedition-specific empty state exists in-canvas, since the camp scene only ever mounts once a game is in progress |
| Gear "why not usable" reason (GEAR-06 UI half, Claude's Discretion) | A short hover tooltip reusing the server-provided `reason` string verbatim (already server-authored per Phase 10's `canUse` reasons — e.g. "Already used this camp", "Not your turn to act"). Resolved default: hover-only, attached to the gear box sprite, dismissed on pointer-out — matches the "must be discoverable and must not be a panel" constraint literally: a tooltip is not a panel |
| Error state | Connection/session errors are unchanged, inherited from the existing `ReconnectingBanner` HTML component (D-08 explicitly keeps it for the viewer's own connection) — no new error copy authored for the canvas itself |
| Destructive confirmation | Delete/restart room: reuses Hanabi's existing two-step confirm copy and mechanism verbatim (`SettingsModal.tsx`) — no new destructive action or confirmation copy is introduced by this phase |
| Mascot click bubble (D-16, SCENE-09) | One short tip or joke line, plain text, bitmap-font-rendered, dismissed on next click or after a few seconds. Resolved default: keep a short static rotation of 3–5 placeholder lines (e.g. "Psst — the Sun always wins.") in a plain array in the mascot's registry entry; Phase 14 can swap the array's content without touching the interaction mechanism |

## Canvas-Specific Contract (supplementary — not in the base template, required for this phase's Phaser surface)

| Property | Value | Source |
|----------|-------|--------|
| Stage size | 640×360, fixed 16:9 | D-10 |
