Locked client design:
- Resume rule (D-01): on `visibilitychange` to visible or on `online`: if latched -> do nothing; else if readyState !== OPEN or (now - lastHeardAt) > interval + pongTimeout -> "reconnect"; else -> "ping" (send ping and arm pong timeout).
- lastHeardAt is updated on EVERY inbound frame (including the raw pong) before JSON parsing, and set to now on every `open`.
- Heartbeat keeps running while hidden (server SOCKET_STALE_MS accounts for Chrome's 60s throttle); pings are sent only when readyState === OPEN and not latched.
- Status on non-terminal close: view !== null -> "reconnecting"; view === null -> "connecting". onOpen keeps "reconnecting" if current status is "reconnecting", else sets "joining". Terminal statuses (superseded/abandoned/refused/join_failed) are never overwritten by close/open bookkeeping.
- Test-only overrides: NEXT_PUBLIC_HEARTBEAT_INTERVAL_MS and NEXT_PUBLIC_HEARTBEAT_PONG_TIMEOUT_MS (integer >= 250 wins, else constant). Production never sets them.
