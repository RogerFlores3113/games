<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser form → `POST /api/room` | Display name and variant are untrusted user input |
| Vercel route → client | The minted code is the only thing returned; no room state exists yet |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-03 | Tampering | `POST /api/room` | mitigate | Body validated with `DisplayNameSchema` + `VariantSchema` from `@games/schema` before use; failures return 400 with a fixed `bad_request` code and no echo of the submitted value. The route is not the authority on anything — the Durable Object re-validates the display name on `join`, so a bypassed API route grants nothing. |
| T-1-16 | Spoofing | room-code entropy | accept | 32^6 ≈ 1.07e9 on a deliberately speakable 6-char code (D-01). Guessing a code grants a lobby seat at most; occupied seats are protected by the 24-char seat token (T-1-01). Accepted at this threat model. |
| T-1-22 | Denial of Service | unlimited code minting | accept | The route mints a string and creates no server state — no Durable Object, no storage write — so minting is cheap and reaping is automatic via ROOM-08 idle GC on the (never-created) room. Rate limiting is unnecessary because the expensive resource is not allocated here. |
| T-1-23 | Information Disclosure | clipboard / sessionStorage | accept | `sessionStorage` carries only a display name the user just typed, scoped to the tab, keyed by room code. No token or credential is stored by this plan; the seat token is written to `localStorage` by Plan 09 only after the server mints it. |
| T-1-24 | Information Disclosure | UI contrast failure | mitigate | `--color-text` on `--color-accent` (≈1.63:1) is forbidden by the UI-SPEC and grep-asserted; every accent fill takes a `--color-bg` label at ≈10.9:1. This is an accessibility control, tracked here because it is a verifiable output property like any other. |
</threat_model>
