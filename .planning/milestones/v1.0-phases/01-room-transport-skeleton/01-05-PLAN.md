Add to `apps/worker/src/seat-identity.ts`:

`resolveSeatByToken(seats: readonly Seat[], presented: string | undefined): Seat | null` — returns `null` immediately for `undefined`, for a string whose length is not `SEAT_TOKEN_LENGTH`, or for a value failing `SeatTokenSchema.safeParse`. Compare by iterating ALL seats and accumulating the match rather than early-returning on the first hit, so comparison cost does not vary with position; use a constant-time-style equality helper that XORs char codes across the full token length instead of `===` short-circuiting. This is defense-in-depth, not a hard requirement at this threat model, but it costs five lines and removes an entire question later.

`rebindSeatConnection(bindings: SeatBindings, seatId: string, newConnectionId: string): { bindings: SeatBindings; supersededConnectionId: string | null }` — `SeatBindings` is a plain `Record<seatId, connectionId>` map (in-memory, reconstructable, NOT persisted — a connection id is meaningless after hibernation eviction). If the seat already had a different connection id bound, return it as `supersededConnectionId` so the caller can send `{type:"superseded"}` and close that socket with `SUPERSEDED_CLOSE_CODE`. Newest socket always wins (D-08). The seat's persisted state is untouched by this function — that is the whole point: rebinding is a connection-layer concern and must never mutate `RoomState`, which is how "Phase 1 only needs this to not corrupt seat state" is guaranteed structurally.

Write `seat-identity.test.ts` covering:

RT-07 — a seat exists with token T; `resolveSeatByToken(seats, undefined)` is `null`; `resolveSeatByToken(seats, "")` is `null`; `resolveSeatByToken(seats, roomCode)` is `null` (a room code is never a valid seat token — the exact confusion RT-07 guards); `resolveSeatByToken(seats, T.slice(0,-1) + "X")` is `null`; only the exact token resolves.

Entropy/shape — 1,000 minted seat tokens are all distinct, all length 24, and none is composed solely of `ROOM_CODE_ALPHABET` characters across a sample (assert at least one minted token contains a character outside that alphabet, proving the alphabets really differ); 1,000 minted room codes are all length 6 and match `^[ABCDEFGHJKLMNPQRSTUVWXYZ23456789]{6}$`.

D-08 — binding seat `s1` to `c1` then to `c2` returns `supersededConnectionId === "c1"` and leaves `bindings["s1"] === "c2"`; binding the same connection id twice returns `null` for superseded (a reconnect that reuses an id is not a takeover); binding a DIFFERENT seat does not disturb `s1`'s binding; and `rebindSeatConnection` never receives or returns a `RoomState` (assert by type — the function signature has no `RoomState` parameter).

Add a fast-check property: for arbitrary strings, `resolveSeatByToken` never throws and returns `null` unless the string exactly equals a known token.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `resolveSeatByToken` | The presented seat token is fully attacker-controlled; everything downstream trusts its verdict |
| room link holder → occupied seat | Anyone with the shareable code can open a socket; only token possession grants an existing seat |
| connection map ↔ persisted room state | Deliberately separated — rebinding cannot write room state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Spoofing | `mintSeatToken` / `resolveSeatByToken` | mitigate | 24-char nanoid over the default 64-char alphabet (~143 bits), CSPRNG-backed, minted server-side only. Resolution requires exact full-length equality; the room code, a truncated token, and an empty string all resolve to `null`. This is the RT-07 control. |
| T-1-02 | Tampering | second-tab rebinding | mitigate | `rebindSeatConnection` operates on an in-memory connection map with no `RoomState` parameter (grep-asserted), so a stale tab physically cannot write seat state. The superseded connection is returned to the caller for an explicit `{type:"superseded"}` + close 4001 rather than being silently dropped (D-08). |
| T-1-15 | Information Disclosure | token comparison timing | mitigate | Full-length XOR comparison over all seats with no early return. Accepted as defense-in-depth; the friend-group threat model does not require it, but it removes a class of question for free. |
| T-1-16 | Spoofing | room-code brute force | accept | 32^6 ≈ 1.07e9 keyspace on a 6-char speakable code is not brute-force-proof, and D-01 deliberately trades entropy for speakability. Guessing a code grants a LOBBY seat or a refusal — never an occupied seat (T-1-01 covers that) and never game state a seat would not otherwise see. Rate limiting is out of scope for the stated friend-group threat model; revisit only if the room ever holds anything of value. |
| T-1-17 | Denial of Service | code/token collision | mitigate | `mintRoomCode` and `mintSeatToken` validate through their branded schemas at mint time; uniqueness within a room is asserted by the 1,000-sample tests. Cross-room code collision would route two rooms to one Durable Object; at this scale and keyspace the probability is negligible and accepted. |
</threat_model>
