# Phase 06.2 Plan 01: Shared Discard Order Summary

**Server-authoritative `discardOrder` on `HanabiState`/`HanabiView`, a `reorderDiscard` action any seated player may submit at any time, and a 200-run property proof that the arrangement always stays a permutation of the pile and identical across every seat.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 3
- **Files modified:** 15 (1 created, 14 modified)

## Accomplishments
- `HanabiState.discardOrder` / `HanabiView.discardOrder` / `HanabiViewSchema.discardOrder` land end to end in one commit, with every existing action branch (`applyPlay`, `applyDiscard`, `applyClue`, `applyReorder`) carrying or appending the field field-by-field (no spread)
- `canReorderDiscard`/`applyReorderDiscard`/`isReorderDiscardRequest` give any seated player an off-turn, resource-free way to rearrange the shared discard pile, validated as an exact permutation with a seated-actor gate
- `discard-order.property.test.ts` proves over 200 random games per variant that `discardOrder` never drifts from being a permutation of `discard`, that every seat's projected order is identical after a reorder, and that a newly discarded card always appends last
- `clue-facts.test.ts` proves `positiveClues` is monotonically growing (previous entries always a prefix), the assumption Phase 06.2's hint display work depends on

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Rewrote `applyHanabiAction`'s dispatch tail as explicit per-type checks**
- **Found during:** Task 1 (discardOrder field through state/actions/projection/schema)
- **Issue:** Adding the `reorderDiscard` variant to `HanabiAction` in Task 1 (before Task 2 adds its handler) broke the existing dispatch's final implicit-`else` line (`return applyClue(state, actorSeatId, action.targetSeatId, action.clue)`), since TypeScript could no longer narrow the fallthrough type to just `"clue"` — it now had to consider `"clue" | "reorderDiscard"`, so `action.targetSeatId`/`action.clue` were no longer valid on the union. This is exactly the kind of "missing field is a `tsc` error" discipline documented in `actions.ts`'s file header, working as intended.
- **Fix:** Made the `"clue"` branch an explicit `if`, and added a final fallback that returns `{ ok: false, error: "invalid_action" }` for the not-yet-handled `reorderDiscard` case in Task 1's commit, then replaced that fallback with the real `applyReorderDiscard(...)` call in Task 2's commit once `canReorderDiscard`/`applyReorderDiscard` existed.
- **Files modified:** `packages/rules/src/hanabi/actions.ts`
- **Verification:** `npx tsc -b packages/rules packages/schema apps/worker apps/web` exits 0 after both Task 1 and Task 2; `npx vitest run --project rules` green after each.
- **Committed in:** `c8a5399` (Task 1, temporary fallback), `332c0f2` (Task 2, real dispatch)

**2. [Rule 1 - Bug] Updated every pre-existing `HanabiState`/`HanabiViewSchema` test fixture outside the plan's explicit file list**
- **Found during:** Task 1, running `tsc -b` across the full monorepo
- **Issue:** The plan's Interfaces block named three fixtures (`actions.test.ts`, `legality.test.ts`, `projection.test.ts`) to update, but `endgame.test.ts`, `hanabi-leak-check.test.ts`, and `conservation.property.test.ts` (packages/rules) plus `packages/schema/src/games/hanabi.test.ts` and `apps/worker/src/seat-projection.test.ts` also construct typed `HanabiState`/`HanabiViewSchema`-shaped literals that fail to type-check or fail strict-schema validation once `discardOrder` became a required field, exactly as RESEARCH.md's Pitfall 5 predicted for the schema side.
- **Fix:** Added `discardOrder: []` (or a matching id array) to each fixture, in the same style as the three named fixtures.
- **Files modified:** `packages/rules/src/hanabi/endgame.test.ts`, `packages/rules/src/hanabi/hanabi-leak-check.test.ts`, `packages/rules/src/hanabi/conservation.property.test.ts`, `packages/schema/src/games/hanabi.test.ts`, `apps/worker/src/seat-projection.test.ts`
- **Verification:** `npx tsc -b packages/rules packages/schema apps/worker apps/web` exits 0; `npx vitest run --project rules` green.
- **Committed in:** `c8a5399` (Task 1)
