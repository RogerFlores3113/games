# Phase 06.2 Plan 18: Discard group-by-suit action Summary

**A "group by suit" button in both discard views re-sorts the shared `discardOrder` for every player through the existing `reorderDiscard` action, and dragging still works on the result — closing UAT gap 10 without adding a second server action or a local view toggle.**

## Performance

- **Duration:** ~50 min
- **Tasks:** 3
- **Files modified:** 8

## Accomplishments
- `groupedBySuitOrder(discard, suitOrder)` in `hanabi-discard-drag-logic.ts`: sorts by suit position in `suitOrder`, then rank ascending, then existing index — deterministic, idempotent, always an exact permutation of the input, never mutates, and an unknown suit sorts last instead of throwing (T-06.2-42)
- `discard-group-by-suit` (compact board header) and `discard-overlay-group-by-suit` (expanded overlay header) both call a handler in `HanabiBoard` that computes the grouped order and dispatches `act({ type: "reorderDiscard", cardIds })` — the same chokepoint a drag uses, so `canReorderDiscard`'s server-side permutation check (D-26) is the sole legality gate here too
- Both controls are disabled with fewer than two discarded tiles or whenever `HanabiBoard` withholds the handler (reconnecting/ended)
- A two-page Playwright proof discards mixed tiles, groups them on page A, asserts page B sees the identical order with no refresh, that the order survives a page B reload, and that a subsequent drag on page B still produces an ordinary reorder both pages agree on

## Decisions Made
- Disabled-when-reconnecting/ended is implemented by `HanabiBoard` passing `undefined` for the handler prop rather than by threading a new `ctx`/`controlsDisabled` prop into `Table` — the plan's own acceptance criteria already phrased the disabled condition as "or when the handler is absent," so this was the intended shape, not a shortcut
- The suit-order argument is always derived from `game.stacks` at the call site (never a hardcoded suit list), so grouping is correct for Rainbow/Black without any variant-specific branch

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] New button's out-of-flow touch target intercepted discard-toggle's clicks**
- **Found during:** Task 3, running the new e2e test (`discard-group-by-suit`'s click timed out — Playwright reported `discard-toggle`'s hit-area span intercepting pointer events)
- **Issue:** Task 2 gave `discard-group-by-suit` the same out-of-flow 44px touch-target pattern `discard-toggle` uses (a `span` with `inset: calc((44px - 14px) / -2)` = -15px on all sides). With the two 14px visible boxes only `--space-xs` (4px) apart, their 44px hit areas overlapped by ~26px, so a click aimed at either button could resolve to the wrong one's — or a swallowed — hit-area span. This is the same class of bug 06.2-10 fixed (sibling swallows click), but from two full touch targets colliding rather than a sibling/descendant ordering mistake.
- **Fix:** Made each button's hit-area span asymmetric: full -15px expansion on the three outward-facing sides (top/bottom/away-from-neighbor), and only -2px (half the row gap) on the inward-facing side, so the two touch targets meet at the gap's midpoint without overlapping.
- **Files modified:** apps/web/components/hanabi/Table.tsx
- **Verification:** `npx playwright test e2e/hanabi-table-polish.spec.ts` (18/18) and the full `npx playwright test` (44/44) both green after the fix; `npm test` (899/899) and `npx tsc -b apps/web` unaffected (no test exercised the touch-target geometry directly, only the click's actionability)
- **Committed in:** 103cf13 (Task 3 commit — surfaced and fixed alongside the new e2e test)
