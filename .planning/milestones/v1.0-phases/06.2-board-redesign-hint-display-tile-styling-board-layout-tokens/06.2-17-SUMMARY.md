# Phase 06.2 Plan 17: Translucent tile-colour overlay Summary

**Tile-colour presets are now `color-mix(..., transparent)` washes painted on an overlay span above the card art (not the tile's own opaque background), proven translucent by an e2e alpha<1 assertion on the computed colour.**

## Performance

- **Duration:** ~55 min
- **Tasks:** 3
- **Files modified:** 6

## Accomplishments
- Every `TILE_COLOR_PRESETS` entry is a `color-mix(in srgb, var(--color-*) N%, transparent)` value (45% for slate, 55% for the other four), never opaque and never a hex literal
- `OwnHandCard`/`TeammateCard` paint the preference on a new overlay span above the card art and below the hint/identity chrome; the tile container's own background is now the constant `var(--color-surface)`
- `TILE-03`'s e2e proof reads the overlay's computed colour, parses it as either `rgba(...)` or CSS Color 4 `color(srgb ... / a)` (the form Chromium actually renders `color-mix()` as), and asserts alpha < 1 — plus that the slot's own background stays constant across a preset change

## Decisions Made
- Reordered the overlay testid to put `tile-color-overlay` first rather than last, to avoid colliding with `data-testid^="own-hand-slot-"` / `data-testid^="other-hand-card-"` prefix selectors already in use (see Deviations below for the full incident)
- Gave the teammate overlay an explicit `z-index: 11` since the visible card's art/identity span is `position:relative; z-index:10` — without it the overlay would render (per CSS3 stacking rules, step 6 vs step 7) underneath the opaque card art despite coming later in the DOM, defeating the entire point of the gap

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Overlay testid collision with existing prefix-based selectors and production fly-to-animation code**
- **Found during:** Task 2/3, running the full `npm test` and `npx playwright test` suites
- **Issue:** The plan's literal testid suggestion (`own-hand-slot-{N}-tile-color-overlay` / `other-hand-card-{id}-tile-color-overlay`) starts with the exact prefix several existing selectors match on: e2e's `OWN_HAND_SLOT_SELECTOR`, `teammateHandCardIds()`, several `.count()`/`.first()` assertions in `start-game.spec.ts`/`hanabi-realtime.spec.ts`, and — critically — production code in `apps/web/components/hanabi/FlyToLayer.tsx`, which slices `"other-hand-card-".length` off a matched testid to key its fly-to-animation source-rect map. With the plan's naming, the overlay span would have been picked up as a second "card", corrupting hand-order assertions (2 failing e2e tests confirmed this: HAND-01, HAND-03) and silently breaking the fly-to-animation's rect lookup for the real card in production.
- **Fix:** Renamed both overlay testids to put the shared literal (`tile-color-overlay`) FIRST instead of last: `tile-color-overlay-own-hand-slot-{N}` / `tile-color-overlay-other-hand-card-{id}`. No consumer code needed touching — the overlay's testid simply no longer matches any existing prefix selector.
- **Files modified:** apps/web/components/hanabi/OwnHandCard.tsx, apps/web/components/hanabi/TeammateCard.tsx, apps/web/lib/own-hand-render.test.ts, e2e/hanabi-table-polish.spec.ts
- **Verification:** Full `npx playwright test` (43/43) and `npm test` (885/885) both green after the rename; manually confirmed FlyToLayer.tsx's `other-hand-card-` prefix scan no longer matches the overlay span
- **Committed in:** 20d2b54 (Task 3 commit — surfaced and fixed alongside the e2e re-point)

**2. [Rule 1 - Bug] Pre-existing D-10 byte-identical-segment test broke on the new overlay markup**
- **Found during:** Task 2 verification
- **Issue:** `own-hand-render.test.ts`'s "every own-hand card-back segment is byte-identical across slots" test split markup on the literal string `data-testid="own-hand-slot-`, which (before the testid rename above) also matched the new overlay's suffixed testid, producing spurious segments with no `<svg>` to find
- **Fix:** Changed the split to a regex matching the exact slot testid (`data-testid="own-hand-slot-\d+"`) only
- **Files modified:** apps/web/lib/own-hand-render.test.ts
- **Verification:** `npx vitest run --project web own-hand-render` green
- **Committed in:** 162ba1f (Task 2 commit)
