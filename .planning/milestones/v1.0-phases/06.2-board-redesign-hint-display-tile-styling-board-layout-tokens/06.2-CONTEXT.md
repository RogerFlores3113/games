# Phase 06.2: Board Redesign - Context

**Gathered:** 2026-09-17
**Status:** Ready for planning

<domain>
## Phase Boundary

Rework the Hanabi table's visual language so it reads like a physical tile game, replace the automatic clue-mark display with direct hint indicators on the tile itself, and give the discard pile a shared, player-arranged order.

Source of scope: the owner's 17 follow-on requests recorded under `## Gaps` in `.planning/phases/06.1-table-polish-firework-art-notes-drag-audio/06.1-HUMAN-UAT.md`, made at the 06.1 sign-off ("good improvements!"). These are new requests, not defects in 06.1.

Six scope groups:
1. **Hint display** — clue-coloured tile highlight, number clue shown on the tile back, "keep hints visible" toggle. This replaces the current automatic clue-mark pips.
2. **Hand interaction** — tiles shift aside during a drag reorder; an always-visible faint note box above each tile.
3. **Tile and board styling** — tile background distinct from the board, wooden board surface, player-settable tile colour.
4. **Board layout** — labelled Play (top) and Discard (bottom) areas with subtle outlines, clue and fuse tokens as art on the right, spent tokens removed, deck counter between the two areas.
5. **Played stack** — every firework in a stack visible, not just the top card.
6. **Shared discard order** — every player sees the same arrangement; any player may rearrange it. The only server-side item in the phase.

Not in this phase: variant support (Phase 7), and any rules-engine change beyond what the shared discard order requires.

</domain>

<decisions>
## Implementation Decisions

Discussion ran in `--auto` mode: every choice below was selected by Claude as the recommended default, except D-01, which the owner answered directly. Each is a starting position for planning, not a hard constraint, and all of them surface again at this phase's owner sign-off.

### Hint display (replaces the automatic clue marks)

- **D-01 (owner, verbatim):** "The new format was the sentences following it. Remove the automatic tile notes - instead, the indicator for hints is what i told you, and there's a toggle that keeps the hints visible - thus making the hint indicators into automatic tile notes." The hint indicators ARE the new note format. The current `CandidateStrip` pip rows are removed, not kept alongside.
- **D-02:** A colour clue tints the touched tile in that suit's own `--color-suit-*` hue. The existing `--color-card-glow` yellow stops being the generic clue signal.
- **D-03:** A number clue renders that numeral on the tile back of the touched tile. On own-hand tiles this is the only place a numeral appears, since 06.1 removed numerals from card faces.
- **D-04:** Colour identity must not be the sole carrier, per the project's colourblind rule. A colour clue also keeps a non-colour marker on the tile (shape, border treatment, or the suit silhouette) so the highlight survives a grayscale check.
- **D-05:** "Keep hints visible" is a per-player client-side toggle, persisted through `safe-storage.ts` like the audio and discard-view preferences. On: hint indicators persist until the card leaves the hand. Off (default): they clear once the next player has acted.
- **D-06:** Accumulated hints stack. A tile told "red" then "3" shows both. The exact composition is a design decision for the plan.
- **D-07 (owner-confirmed 2026-09-17):** Negative information (ruled-out suits and ranks) is dropped from the tile display along with the pip rows. The owner was asked directly, shown the alternatives (keep it small and quiet, or reveal it on hover/click), and chose "Let it go" — the cleanest board, closest to a physical game. Players track ruled-out suits and ranks in their own note box or in their head. Do not reintroduce a ruled-out indicator.

### Hand interaction

- **D-08:** During a drag reorder, the other tiles slide aside to open a gap at the drop position, animated, with a static end-state under `prefers-reduced-motion` per the project's existing pattern.
- **D-09:** The note box is always visible above each own tile, with a barely-visible outline, click-to-type, and autosave on change (debounced) rather than only on Enter or blur. It replaces the current pencil-icon `NoteChip`.
- **D-10:** Notes stay private and browser-local, keyed by card id in `hanabi-notes.ts`, with the existing prune-on-leave and clear-on-game-end lifecycle. The 20-character cap is reconsidered during the plan now that the box is always visible.

### Tile and board styling

- **D-11:** The board gets a wooden surface. Prefer a CSS-generated texture (layered gradients) over another downloaded image, so the phase adds no new asset or licence obligation. If the CSS version looks poor, fall back to a licensed image recorded in `CREDITS.md` as 06.1 did.
- **D-12:** Tiles get a raised, opaque surface distinct from the board: a lighter fill plus an edge treatment, so a tile reads as an object resting on the board.
- **D-13:** The player's tile colour is a client-side personal preference, persisted through `safe-storage.ts`, affecting only that player's view. It never travels to the server or to other players.
- **D-14:** The colour picker offers a small fixed palette of preset tile colours rather than a free colour wheel, so every option stays within contrast limits against the suit colours, the glyphs and the hint tints.
- **D-15:** The 06.1 city-at-night background stays behind the board. The wooden surface belongs to the board area, not the whole page.

### Board layout

- **D-16:** Play at the top, Discard at the bottom, deck counter between them, clue and fuse tokens on the right, as the owner described.
- **D-17:** Each area gets a subtle outline and a text label ("Play", "Discard").
- **D-18:** Clue tokens are black discs with a blue question mark, in a vertical line. Fuse tokens are black discs with a yellow explosion with an orange-red rim, beside the clue tokens.
- **D-19:** Spent tokens are removed from the board rather than dimmed, so the remaining count is read by counting tokens. Keep a text count alongside for accessibility and for tests.
- **D-20:** Token art is drawn as inline SVG in the existing `suit-visuals.ts` style, not as image files.
- **D-21:** The deck counter is "N x [card back]" using the picture-frame `FireworkCardBack`, sized small.
- **D-22:** Played stacks show every card in the stack, fanned or stepped so each rank is visible, rather than only the top card.

### Shared discard order

- **D-23:** The discard order is shared game state on the server, not a client preference, so everyone sees the same arrangement.
- **D-24:** A new `reorderDiscard` action follows the `reorder` precedent from 06.1-01: legal off-turn, consumes no turn, token or fuse, records no history entry, and rides the existing `actionId` idempotency and status gate in `applyGameAction`.
- **D-25:** Any seated player may reorder the discard at any time while the game is in progress. It is a shared workspace, not a turn action.
- **D-26:** Validation mirrors `canReorder`: the submitted ids must be an exact permutation of the current discard ids. A stale submission after a new discard lands is rejected, and the client re-reads from the server view.
- **D-27:** Last write wins on conflict. No locking or merge. With a small group on a voice call this is adequate, and rejection-on-stale already prevents a lost card.
- **D-28:** The order field is computed once in the public section of `toHanabiPlayerView` and returned identically in both the seated and fail-closed branches, never per seat.
- **D-29:** Follow the `reorder` precedent and validate with a hand-rolled exact-key guard in `actions.ts` rather than adding a zod schema, so the two reorder actions stay consistent. The scout flagged this inconsistency with `packages/schema`; resolving it project-wide is out of scope here.

### Claude's Discretion

Exact visual composition throughout: how a colour tint and a numeral combine on one tile, the fan geometry for played stacks, token disc sizes, the wooden texture recipe, and the preset tile-colour palette. The owner reviews all of it at sign-off.

</decisions>

<code_context>
## Existing Code Insights

### Reusable assets
- `apps/web/lib/safe-storage.ts` — the one localStorage wrapper, SSR-safe and non-throwing. The keep-hints toggle and the tile-colour preference both use it. Do not add a second wrapper.
- `apps/web/lib/suit-visuals.ts` and `SuitGlyph.tsx` — the inline-SVG art system, including the `useId` gradient-id technique from the rainbow work. Clue and fuse token art follows it.
- `FireworkCardBack` — the picture-frame back, reused for the deck counter and as the surface a number clue is drawn on.
- `apps/web/lib/hanabi-notes.ts` — note storage keyed by card id, with `pruneNotesForSeat` and `clearNotesForRoom`. The new note box keeps this and changes only the UI.
- The `reorder` action across `actions.ts`, `legality.ts`, `state.ts` and `HanabiBoard.tsx`'s `HanabiActionRequest` — the worked example for `reorderDiscard`.
- `useHandDrag.ts` and `hanabi-drag-logic.ts` — the drag machinery the shift-aside preview builds on, including `applyPendingOrder` for optimistic order.

### Established patterns
- **Identity boundary (D-15):** own-hand components receive ids and `facts` only, never a card object, and are covered by a source scan plus a byte-identical render test.
- **Out-of-flow touch targets:** an absolutely positioned `aria-hidden` inset span gives a 44px hit area while the visible control stays icon-sized. Used by the discard toggle and note chip; no shared helper exists, so a new control hand-rolls it or the plan extracts one.
- **Reduced motion:** every animation has a paired `prefers-reduced-motion` block that swaps in the static end state rather than removing the effect.
- **Transient highlights use refs, not effect cleanup**, because `game` is a new object every server frame. The stack-flash and clue-touch animations document this; the hint indicators must follow it or highlights stick or cancel early.

### Integration points
- `Table.tsx` — the whole tableau, and the file the layout rework mostly lands in.
- `HanabiBoard.tsx` — the vertical bands and the action dispatcher `act()`, where the new toggle, colour picker and `reorderDiscard` request wire in.
- `MarksZone.tsx`, `CandidateStrip.tsx`, `Hand.tsx` — what the hint rework replaces or reshapes.
- `toHanabiPlayerView` — where shared discard order joins the public fields.

### Risks the scout flagged
- The 1280x720 no-scroll fit is held by scattered constants (`gap-[3px]`, `py-[3px]`, fixed 28/20/16/48/64px heights, `min-h-0 flex-1` on the Table wrapper). There is no single budget to check. This phase adds height in several places at once, so the fit test will break unless the plan treats the budget as a first-class task. Removing the 28px pip band frees room that the note box and token art then spend.
- `own-hand-source.test.ts`'s file list must be updated by hand for every new own-hand component.
- Adding a shared field to the projection risks a per-seat divergence if it is not computed in the public section.

</code_context>
