Close UAT gap 10: add a "group by suit" action that re-sorts the shared discard order for everyone, after which players can still drag.

The owner was asked and chose a visible, shared re-sort rather than a private view toggle, so it goes through the existing `reorderDiscard` action and is subject to the same server-side permutation validation as a drag.
Output: a pure suit-sort helper, a button in both the board's discard area and the expanded overlay, and a two-page browser proof.

<interfaces>
The action already exists end to end — this plan adds a second way to trigger it, not a new action:
- `HanabiActionRequest` in `HanabiBoard.tsx` already carries `{ type: "reorderDiscard"; cardIds: string[] }`, dispatched through `act()`.
- `packages/rules/src/hanabi/legality.ts`'s `canReorderDiscard` validates that the submitted ids are an exact permutation of the current discard ids and rejects a stale submission (D-26); `applyReorderDiscard` consumes no turn, token or fuse and records no history entry (D-24).
- `apps/web/lib/hanabi-discard-drag-logic.ts` already exports `reorderedDiscardIds`, `discardDropIndex`, `requestForDiscardDrop` and re-exports `applyPendingOrder`; `DiscardDropRequest` is `{ type: "reorderDiscard"; cardIds: string[] }`.
- `useDiscardDrag` owns the optimistic `pendingOrder` while a drag is in flight; `Table.tsx` composes it via `applyPendingOrder(serverOrderedDiscard, discardPendingOrder)`.

Canonical suit order: `game.stacks` is already in variant suit order, so `game.stacks.map((s) => s.suit)` is the ordering to sort by — never a hardcoded suit list, which would be wrong for Rainbow/Black.

Disabled conditions to honour: the button must be disabled when the discard pile is empty, when fewer than two tiles are present, and whenever the existing `ctx` says controls are disabled (reconnecting or ended) — the same gate every other action control uses.
</interfaces>

    - `groupedBySuitOrder(discard, suitOrder)` returns ids sorted by suit position in `suitOrder`, then by rank ascending, then by the tile's existing index — a total, deterministic order.
    - The result is always an exact permutation of the input ids: same length, same set, no duplicates.
    - Calling it twice on the already-grouped sequence returns the same order (idempotent).
    - A card whose suit is absent from `suitOrder` sorts last rather than throwing.
    - An empty pile returns an empty array.
