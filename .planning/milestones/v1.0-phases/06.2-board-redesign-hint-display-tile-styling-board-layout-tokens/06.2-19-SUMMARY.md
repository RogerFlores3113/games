## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed a double-counted page-level chrome constant in the e2e worst-case ledger check**
- **Found during:** Task 1
- **Issue:** `e2e/start-game.spec.ts`'s worst-case test compared `tableauBox.height` against `TABLE_BAND_MIN_PX + BOARD_CHROME_PX`, but `Table.tsx`'s own inline style sets `tableau`'s height to exactly `BOARD_INNER_PX + 2 * BOARD_PANEL_PADDING_PX`, which already equals `TABLE_BAND_MIN_PX` — `BOARD_CHROME_PX` is separate page-level chrome (`<main>`'s padding + inter-band gaps), not part of `tableau`'s own box. The bug was invisible under the pre-existing 40px tolerance.
- **Fix:** Compared `tableauBox.height` against `TABLE_BAND_MIN_PX` alone and tightened `TOLERANCE_PX` from 40 to 2, documenting the correction inline.
- **Files modified:** `e2e/start-game.spec.ts`
- **Verification:** `npx playwright test e2e/start-game.spec.ts -g "UI-11 worst case"` passes with the tightened comparison
- **Committed in:** `a44c1fe` (Task 1 commit)

**2. [Rule 1 - Bug] The random-play strategy in a bounded loop cannot guarantee a stack advance**
- **Found during:** Task 2
- **Issue:** An initial implementation of the fixed-geometry test reused the existing worst-case test's random own-hand-play strategy to reach "at least one stack advanced." Empirically, that strategy reliably misplays into 2 fuse losses early (random cards are legal to click but not necessarily legal to play), after which the loop's own safety rule switches to discard-only for the rest of its 60 iterations — so `maxStackRank` stays 0 even after 60 turns (confirmed: the existing worst-case test, which has no advance requirement, exhibits exactly this outcome in its own logged run, `maxStackRank=0`).
- **Fix:** Replaced the stack-advance mechanism with a deterministic one: read a teammate's real card identity (visible to every other seat per Hanabi's own client-side rules, `card-identity`'s sr-only text), find a rank-1 card of a currently-empty stack, clue it specifically (not a random legal clue), and have that exact teammate play it next turn using the resulting hint-numeral overlay to find the right slot. This also surfaced and required handling a related rule I'd initially overlooked: discarding refunds a clue token and is illegal once clue tokens are full (standard Hanabi rule), so the fallback action logic needed to give a clue instead of discard whenever tokens are at the 8-token max.
- **Files modified:** `e2e/start-game.spec.ts`
- **Verification:** Ran the new test 4 times consecutively with no flake; ran the full `e2e/start-game.spec.ts` file and the full `npx playwright test` suite (45 tests) — all green
- **Committed in:** `40595e2` (Task 2 commit)
