# Phase 06.2 Plan 07: Board Redesign — Wooden Two-Column Tableau Summary

**Table.tsx rebuilt as a wooden `.board-surface` panel — labelled Play area (fanned stacks) above a deck counter above a labelled Discard area (rendered in the server's shared discardOrder), with the clue/fuse TokenColumn stretched to match on the right — and the UI-11 1280x720 overflow is now definitively root-caused to HanabiBoard.tsx's bottom controls row, not this component.**

## Performance

- **Duration:** ~55 min
- **Completed:** 2026-09-17
- **Tasks:** 3 completed
- **Files modified:** 3 (1 created, 2 modified) across the three task commits, plus 1 doc file (deferred-items.md)

## Accomplishments

- `Table.tsx`'s `tableau` section is now a single `items-stretch` flex row with two children: a fixed-height (`LEFT_COLUMN_PX`) left column stacking Play (outlined, labelled, fanned `PlayedStack`s) / Deck counter (`FireworkCardBack` + `deckCountText`) / Discard (outlined, labelled, `discardOrder`-sequenced tiles), and a `TokenColumn` right column stretched to the same height so it can never force the board taller.
- Every card in every played stack is visible via `PlayedStack`'s horizontal fan (BOARD-05); clue/fuse tokens are physical art that disappears as spent, with always-present accessible counts (BOARD-02/03, via `TokenColumn`).
- The Discard area renders every tile in `game.discardOrder`'s exact order (DISC-01's presentation half), resolved defensively: an id with no matching discard entry is skipped, and any discard entry missing from `discardOrder` is appended at the end rather than hidden (T-06.2-15).
- The board carries the `.board-surface` wooden treatment (TILE-02); the 06.1 city-at-night `.table-backdrop` background is untouched and remains visible around the panel's edges.
- Every pre-existing testid the drag system and e2e suite depend on survived the rework (`tableau`, `play-zone`+`data-drop-state`, `played-stack-{suit}`+`data-top-rank`/`data-complete`, `clue-tokens`, `fuse-tokens`, `deck-count`+`data-final-round`, `discard-pile`+`data-discard-count`/`data-view`/`data-drop-state`, `discard-toggle`, `drop-reason-play`, `drop-reason-discard`) — proven by `e2e/hanabi-table-polish.spec.ts`'s full 9-test suite passing unchanged.
- Added the mandatory early 1280x720 no-vertical-scrollbar check to `e2e/start-game.spec.ts` per this plan's inherited blocker. It **fails**, and that failure is used diagnostically: measured live at 5 players, `Table.tsx` now renders at ~278px — matching its own `LEFT_COLUMN_PX`/`TABLE_BAND_MIN_PX` budget (260px) for the first time — while the bottom controls row (`HanabiBoard.tsx`'s `OwnHand`/`CardActions`/`CluePicker`/`AudioControls` wrapper) measures 440px against its own `OWN_BAND_PX` budget of 180px, a pre-existing 260px overage previously masked by `Table.tsx` under-using its own budget. Full measurement table is in `deferred-items.md`.

- Discard tiles sized at 40x54 (smaller than `PlayedStack`'s 48x64) to fit the `DISCARD_AREA_PX` budget's tile-row allowance alongside the label row and outline padding, letting the row wrap rather than grow unbounded (T-06.2-16).
