# Phase 06.2 Plan 12: Sourced Wood Board and City-Fireworks Backgrounds Summary

Replaced the owner-rejected CSS-generated board grain and the plain city-at-night background with two license-verified Wikimedia Commons photographs — a warm dark-walnut table-surface close-up for `.board-surface` and a Victoria Harbour fireworks-over-water skyline for `.table-backdrop` — both re-encoded to size-capped WebP and credited in `CREDITS.md`.

## What Was Built

**Task 1 — Sourced, license-verified, and optimized both images.**
Searched Wikimedia Commons categories (`Wood grain`, `Walnut wood`) for a dark, board-game-appropriate wood surface. Rejected several candidates on sight after downloading and previewing them: a glossy orange mahogany veneer (too bright/reflective), raw lumber stacks with paper labels, a weathered grey deck with visible screws, and a bed frame (an object, not a texture). Selected `Oberfläche Wohnzimmertisch.JPG` ("surface of a living-room table") by Martin Lorenz (Commons user Rosenmulde) — a top-down, evenly lit walnut plank close-up with no objects, text, or people — licensed CC BY-SA 3.0, verified via `action=query&prop=imageinfo&iiprop=extmetadata` against the file's Commons page (`LicenseShortName: CC BY-SA 3.0`). Downloaded the 5184×3456 original, resized to 1920px wide with PIL/LANCZOS, re-encoded as WebP quality 80 (118,082 bytes).

For the fireworks image, searched Commons for waterfront-fireworks categories, landing on `Category:Fireworks in Hong Kong`. Selected `Hong Kong firework show.jpg` by Dennis Wong — a wide (5547×3121) long-exposure shot of a multi-burst fireworks display over Victoria Harbour with the lit waterfront skyline in frame — licensed CC BY 2.0, verified the same way (`LicenseShortName: CC BY 2.0`, `Artist: Dennis Wong`). This is a literal match for the owner's request ("a city on the water, with fireworks going off in the background").

Rewrote `CREDITS.md` with three `## <filename>` sections: the existing `city-night.webp` record (kept, marked superseded), and new `wood-board.webp` / `city-fireworks.webp` records with Source URL, Author, Author URL, License, License URL, a quoted license-grant sentence, retrieval date, and modifications, matching the existing record's field format.

**Task 2 — Wired both images into `.board-surface` and `.table-backdrop` (globals.css).**
Rewrote `.board-surface`: `background-color: var(--color-surface)` under-fill, a `linear-gradient(rgba(11, 15, 26, 0.35), rgba(11, 15, 26, 0.35))` darkening scrim over `url("/backgrounds/wood-board.webp")`, `background-size: cover`, `background-position: center`; deleted both `repeating-linear-gradient` grain layers and `background-blend-mode`. Updated the rule's doc comment to state D-11's CSS-first preference is reversed by owner review (06.2 UAT gap 2) via D-11's own documented image fallback. Rewrote `.table-backdrop`'s image url to `city-fireworks.webp`, keeping the existing 0.75 scrim, `cover`, `center`, `fixed` unchanged. Deleted the now-unreferenced `city-night.webp`.

Generalised `background-asset.test.ts` from a single-file check to a table of both new assets (magic bytes, ≤300000-byte cap), a CREDITS.md field-count assertion (≥3 of each field, ≥1 `## wood-board.webp` / `## city-fireworks.webp` section), a `.board-surface` rule assertion (wood url, `cover` sizing, no `repeating-linear-gradient`, no `background-blend-mode`, no hex literal), an updated `.table-backdrop` assertion (fireworks url), the carry-forward no-hex-outside-`@theme` check, and a new assertion that `city-night` no longer appears anywhere in `globals.css`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking issue] upload.wikimedia.org rate-limited original-file downloads for this session's IP**
- **Found during:** Task 1, while downloading the fireworks candidate
- **Issue:** After roughly ten successful full-resolution downloads while previewing wood-texture candidates, `upload.wikimedia.org` began returning HTTP 429 ("Too many requests... instead use thumbnail images in sizes listed on https://w.wiki/GHai") for every original-file request. The block persisted through multiple cooldowns (up to ~10 minutes waited). `commons.wikimedia.org`'s API endpoint (a different host) was unaffected throughout, confirming this was upload-CDN-specific, not a full outage.
- **Fix:** Per the error's own guidance, requested the file at a standard pre-cached thumbnail width (1920px, matching the plan's target resize width exactly) via `/thumb/.../1920px-Hong_Kong_firework_show.jpg`, which succeeded (HTTP 200) throughout the block. The thumbnail is generated by and served from the same Commons infrastructure under the same file's Wikimedia Commons license — not a third-party mirror — and was still re-encoded through PIL to WebP quality 80, satisfying the T-06.2-SC "re-encode before commit" mitigation. Documented in CREDITS.md's `city-fireworks.webp` section under "Modifications".
