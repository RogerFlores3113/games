# Phase 06.2 Plan 08: Discard-Pile Drag Summary

**Any seated player can now pointer-drag any discarded tile — on the board or in the expanded overlay — into a new position; the arrangement is dispatched through `reorderDiscard` via the existing `act()` chokepoint, and a stale drag silently reconciles to the server's confirmed order rather than erroring.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 3 completed
- **Files modified:** 7 (3 created, 4 modified)

## Accomplishments

- `hanabi-discard-drag-logic.ts` provides pure, tested discard-pile drop resolution (`reorderedDiscardIds`, `discardDropIndex`, `requestForDiscardDrop`), reusing `applyPendingOrder` from `hanabi-drag-logic.ts` by import rather than copying it, and performing no legality derivation of its own (the server's `canReorderDiscard` permutation check, from 06.2-01, is the sole gate).
- `useDiscardDrag.ts` gives any seated player a pointer-event drag (never HTML5 DnD) over the discard pile, mirroring `useHandDrag.ts`'s window-listener/ref/timeout architecture exactly, with a single tile-rect zone model since every drop is a reorder (D-25: no ownership check, legal anytime, only gated by `ctx.reconnecting || ctx.ended`).
- `HanabiActionRequest` gained a `reorderDiscard` variant; `HanabiBoard.tsx` calls `useDiscardDrag` unconditionally alongside `useHandDrag`, dispatching through the same `act()` function every other action uses.
- `Table.tsx`'s compact discard tiles are now draggable (pointerdown/ref wiring, drag-lift transform, optimistic pending order applied over the server-resolved sequence).
- `DiscardOverlay.tsx` now takes a `discardOrder` prop and the same drag wiring, rendering tiles in the shared sequence (not suit-grouped) so both views show and edit one arrangement.
- The inherited UI-11 1280x720 blocker (already resolved by a scoped fix before this plan started) stays green: `e2e/start-game.spec.ts`'s fit checks and `e2e/hanabi-table-polish.spec.ts`'s full 9-test suite both pass unchanged after this plan's edits.

## Decisions Made

- Replaced (not merely extended) `DiscardOverlay`'s suit-grouped rendering with the flat, `discardOrder`-sequenced rendering `Table.tsx` uses — see key-decisions above for the full reasoning; both views must show one linear, shared, draggable arrangement.
- `discardDropIndex` uses single-row horizontal-midpoint comparison, matching this codebase's existing axis-simple drop-geometry precedent rather than inventing row/wrap-aware math the plan never asked for.
- Both the board's compact tiles and the overlay's expanded tiles register into the one `useDiscardDrag` tile Map by card id — the visually-topmost view naturally owns the live rect via React's per-render ref-callback re-attachment (the same mechanism `Hand.tsx`'s `registerSlot` already relies on), so a single hook instance serves both presentations without needing two independent drag state machines.
