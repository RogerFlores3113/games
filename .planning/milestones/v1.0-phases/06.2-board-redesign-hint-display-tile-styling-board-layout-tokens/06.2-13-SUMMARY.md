# Phase 06.2 Plan 13: Settings Modal Summary

Moved every non-play preference control (tile colour, volume, mute, hint persistence) out of the bottom controls row and into a new centre-justified `SettingsModal`, opened by a gear icon absolutely positioned in the top right of the board — closing UAT gap 8 per the owner's verbatim instruction and their "move everything in" follow-up.

## What Was Built

**Task 1 — `SettingsModal` component and an embedded tile-colour swatch grid (TDD).**

Wrote `settings-modal-render.test.ts` first (RED — `SettingsModal.tsx` did not exist), then implemented `SettingsModal.tsx`, mirroring `DiscardOverlay.tsx`'s fixed backdrop + `role="dialog"` panel shape: a `rgba(11, 15, 26, 0.7)` scrim, centred flex panel, Escape-to-close via a `window` keydown listener registered only while open, backdrop click closes, panel click stops propagation. The panel renders four labelled rows in order — Tile colour (embedded `TileColorPicker`), Sound (`AudioControls`, unchanged), Hints (the keep-hints toggle button, moved verbatim with its `Eye`/`EyeOff` icons and descendant touch-target span), and a `settings-close` button.

`TileColorPicker` gained an `embedded?: boolean` prop. The swatch-grid JSX (`tile-color-picker-panel` + five `tile-color-swatch-*` buttons) was extracted into a local variable rendered either directly (`embedded`) or behind the pre-existing toggle button (default/omitted) — the default path is byte-identical to its pre-06.2-13 behaviour, verified by a test asserting `tile-color-picker-toggle` still gates the panel and no `tile-color-picker-panel` renders until opened.

**Task 2 — Gear trigger in the top right, bottom row stripped to play controls.**

Added `settingsOpen` state to `HanabiBoard`. The gear trigger is an absolutely positioned (`top`/`right: var(--space-sm)`) child of the in-game `<main>` (now `position: relative`), `data-testid="settings-toggle"`, `aria-label="Open settings"`, `aria-expanded`, a 20px `Settings` lucide icon, and the project's standard out-of-flow 44px touch-target span as a button descendant. `SettingsModal` is rendered as the last child of `<main>` (after `FlyToLayer`, alongside `EndOverlay`), receiving `audio`, `keepHints`, `tileColorId` and their handlers straight from the state `HanabiBoard` already owned — none of that state moved.

Deleted `AudioControls`, the keep-hints toggle button/wrapper, `TileColorPicker`, and the now-empty grouping div (plus its stale `fix(06.2-10)` ordering comment) from `bottom-controls-row`. The row's three remaining children are exactly `OwnHand`, `CardActions`, `CluePicker`. Removed the now-unused `Eye`/`EyeOff`, `AudioControls`, `TileColorPicker` and `CONTROLS_ROW_PX` imports.

Extended `settings-modal-render.test.ts` with a `HanabiBoard`-level render test (a minimal `RoomView`/`HanabiView` fixture, `renderToStaticMarkup`) asserting the default markup contains `settings-toggle` and none of the four relocated control testids.

**Task 3 — Updated the e2e specs that reached the relocated controls directly.**

`hanabi-table-polish.spec.ts`'s TILE-03 test now opens the modal via `settings-toggle`, clicks the swatch, and closes via `settings-close` before/after the reload re-check. HINT-03's keep-hints toggle is reached the same way, both before turning it on and after the refresh persistence check. Added a new test ("settings modal: the gear opens a dialog holding every relocated preference control...") asserting `audio-volume`, `audio-mute-toggle`, `keep-hints-toggle` and `tile-color-swatch-plum` are all visible inside the open modal, and that Escape closes it (`settings-modal` count 0) without disturbing the board (`own-hand` still visible). `start-game.spec.ts`'s UI-11 fit test swaps its `audio-mute-toggle` in-viewport assertion for `settings-toggle`, plus a new assertion that `settings-modal` has count 0 by default.
