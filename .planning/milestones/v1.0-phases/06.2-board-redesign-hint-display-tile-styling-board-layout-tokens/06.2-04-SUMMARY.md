# Phase 06.2 Plan 04: Tile-Borne Hints and the Deleted Pip Band Summary

**Colour clues now tint the tile and show a faint suit silhouette, number clues stamp a numeral on the tile back, tiles gained a raised drop-shadow surface, and the old MarksZone/CandidateStrip pip-row components are deleted along with their guard-test entries and e2e locators.**

## Performance

- **Duration:** ~40 min
- **Completed:** 2026-09-17
- **Tasks:** 3 completed
- **Files modified:** 13 (2 created, 11 modified, 2 deleted)

## Accomplishments

- `HintIndicator.tsx` (`OwnHintIndicator`/`TeammateHintIndicator`) derives a tile's hint display purely from `facts` via `hintDisplayFor`, rendering a `color-mix`-based suit tint plus a faint `SuitGlyph` marker (top-left) and a `hint-numeral` chip (bottom-right) — independent channels, D-06 composition, no ruled-out/negative information anywhere (D-07). 8 render-contract tests plus a no-hex source scan.
- `OwnHandCard`/`TeammateCard` now render the hint overlay directly over the tile, expose a `data-hints` attribute for e2e, and carry the TILE-01 raised surface: a `tileColor` prop (default slate) as the background and a `color-tile-shadow` drop-shadow composed with (not replacing) the existing luminosity glow.
- `Hand.tsx` drops every `MarksZone` render; own-hand slots keep a fixed `NOTE_ROW_PX`-tall note row (imported from `layout-budget.ts`) for the unchanged `NoteChip`; teammate slots lose the band entirely. `hintsVisible`/`tileColor` thread through with safe defaults so `HanabiBoard.tsx` (not yet wired to the keep-hints toggle or colour picker — that's 06.2-05) still compiles and renders hints unconditionally.
- Deleted `MarksZone.tsx`/`CandidateStrip.tsx` and removed `candidateDisplayFor`/`CandidateDisplay`/`CandidateStripProps` from `hanabi-visual-logic.ts` (confirmed no other consumer remained via repo-wide grep before deleting).
- `own-hand-source.test.ts`: replaced `MARKS_ZONE_PATH`/`CANDIDATE_STRIP_PATH` with `HINT_INDICATOR_PATH` and matching identity-boundary scans (facts-only props, no forbidden tokens, no `suit`/`rank` property access).
- `own-hand-render.test.ts`: dropped the `CandidateStripProps` import/assertion, added `hintsVisible`/`tileColor` to the fixture, and replaced the marks-zone assertion with a hint-overlay assertion (verified against a positively-clued fixture, since the base `VISIBLE_HAND` fixture carries no positive clues and would render nothing).
- Repaired both e2e specs: `start-game.spec.ts`'s HIDE-01 check now asserts `data-hints="false"` and no `own-hand-slot-N-hints` element pre-clue instead of querying the deleted marks-zone pip rows; the UI-11 1280x720 fit check swaps `marks-zone-slot-1`/teammate `marks-zone-*` locators for `own-hand-slot-1`/`note-chip-slot-1`/a teammate card locator. `hanabi-table-polish.spec.ts`'s old "clue marks sit above every card" test is rewritten as "no automatic clue-mark overlay renders on an unclued card" (the "sits above" geometry claim no longer applies — hints are now on the tile, not a band above it).
