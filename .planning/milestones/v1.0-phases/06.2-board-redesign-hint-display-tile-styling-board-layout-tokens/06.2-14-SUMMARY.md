# Phase 06.2 Plan 14: Blue Clue Outline, 2x Tokens, No Count Text Summary

Clue tokens now carry the same blue rim stroke as fuse tokens, both token types render at 40px (2x their measured 20px baseline), and the "N clues/fuses left" text is gone from the board — moved to an `sr-only` span inside a now-fixed 8-clue/3-fuse slot grid whose footprint never changes as tokens are spent.

- **Completed:** 2026-09-17T18:56:00Z
- **Tasks:** 2
- **Files modified:** 5

## Accomplishments
- `ClueTokenArt` gained a `--color-suit-blue` rim stroke (`r="10.25"`, `strokeWidth={1.5}`) matching `FuseTokenArt`'s existing rim treatment exactly (UAT gap 4).
- `layout-budget.ts` gained a fixed token-area ledger (`TOKEN_DISC_PX`, `MAX_CLUE_TOKENS`, `MAX_FUSE_TOKENS`, `CLUE_TOKEN_COLUMNS`, `tokenRunHeightPx`, `TOKEN_AREA_HEIGHT_PX`, `TOKEN_AREA_WIDTH_PX`) replacing the old derived `tokenPitchPx`/`MAX_TOKEN_COUNT` — the token area's height (172px) is now proven at module load to fit inside `TABLE_BAND_MIN_PX` (260px), never computed from the left column.
- `TokenColumn.tsx` rewritten as a fixed 8+3 slot grid: every slot always renders (filled with token art or an empty placeholder span), so the rendered footprint is byte-identical at 0 remaining and at full remaining (UAT gap 1).
- The visible "{n} clues left" / "{n} fuses left" text is gone from the board; it survives as an `sr-only` span inside the same `data-testid` container carrying `data-count`, so `table-render.test.ts`'s exact-text assertions and every Playwright spec reading `textContent`/`data-count`/`toBeInViewport` on `clue-tokens`/`fuse-tokens` kept passing unchanged (UAT gap 6).
- Filled slots are clamped to `MAX_CLUE_TOKENS`/`MAX_FUSE_TOKENS` (T-06.2-35) so a malformed/out-of-range server count cannot grow the reserved box.

## Decisions Made
- `TOKEN_DISC_PX = 40` derived directly from the measured pre-review render (20px), not chosen arbitrarily.
- Clue run uses a 2-column grid (not 1 column of 8) because a single vertical run of 8 40px discs (332px) alone exceeds the 260px table-band budget; the plan's two-columns-of-four layout is what makes the fixed 40px size fit at all.
- `tokenPitchPx`/`MAX_TOKEN_COUNT` deleted rather than deprecated — no other file imported them outside the files this plan already rewrites.
- `columnHeightPx` kept as an accepted-but-unused optional prop on `TokenColumnProps`, per the plan's explicit deferral to 06.2-16 (which also removes `Table.tsx`'s call site).
