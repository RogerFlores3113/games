<objective>
Close UAT gap 7: make the tile colour a translucent darkening overlay painted on top of the card, instead of an opaque fill that hides the card entirely.

Purpose: the owner's verbatim complaint — "the rectangles are supposed to be an opaque darker overlay on top of the cards. Changing color should change that overlay too - it should just darken the card underneath it. Instead, it's a solid layer that blocks the card color change from being visible." Today `tileColor` is the container's `backgroundColor` and the card face is painted over it at `z-10`, so the preference is invisible on a teammate tile and only shows at the tile's edges on an own-hand tile.
Output: alpha-carrying presets and an overlay layer above the art, with the own-hand identity boundary untouched.
</objective>

<interfaces>
Current wiring: `HanabiBoard` resolves `tileColorCss` from `TILE_COLOR_PRESETS.find(...)?.cssValue` and threads it to `OwnHand`/`TeammateHand` → `OwnHandCard`/`TeammateCard`, where it becomes the tile element's `backgroundColor`. Layer order inside a tile today (back to front): container background (`tileColor`), the card art span, the luminosity `backgroundFilter` span, the hint indicator, the slot label / identity span at `z-10`, the just-clued flash.

Preset values today are opaque: `var(--color-tile-preset-plum)` etc., plus slate's `color-mix(in srgb, var(--color-surface) 100%, transparent)`.

Binding rules for this change:
- No hex literal outside `@theme` — build alpha with `color-mix(in srgb, var(--color-tile-preset-*) N%, transparent)`, never an rgba literal of a new colour.
- Own-hand identity boundary (D-15): `OwnHandCard` receives `facts` only and is source-scanned by `apps/web/lib/own-hand-source.test.ts` for `exposeSuit`, `data-suit`, `card-identity`, `data-glyph`. The overlay must be a constant, preference-derived layer with no input from suit or rank. No NEW own-hand component file is created by this plan, so that test's hand-maintained file list does not change — do not add entries to it.
- `apps/web/lib/own-hand-render.test.ts` asserts own-hand markup is byte-identical with and without card identity; the overlay must render identically in both cases.

Tests that assert the current opaque behaviour and must be updated in the same task that changes it:
- `e2e/hanabi-table-polish.spec.ts` TILE-03 reads `getComputedStyle(slot).backgroundColor` on `own-hand-slot-1` before and after choosing a preset, asserts it changed, and asserts the other player's slot background is the original value. With the overlay change the slot's own background is constant, so these assertions move to the overlay element.
- `apps/web/lib/tile-color.test.ts` covers the preset table and the storage round-trip.
</interfaces>
