# Phase 6.1 Plan 11: Private Per-Card Notes Summary

Players can now click a small chip above each of their own cards to type a private, browser-local note (capped at 20 characters), which persists across refreshes, follows the card's id through reorders, and is automatically pruned when the card leaves the hand or the game ends — with the note text never touching `onAction`, the socket, or the server.

## What Was Built

**Task 1 — `NoteChip.tsx`:** A "use client" component with props `{ roomCode, seatId, cardId, slotNumber }` and no other imports beyond `hanabi-notes.ts` and `lucide-react`'s `Pencil` icon — no `room-socket`, `room-store`, `nanoid`, `onAction`, or `send(` anywhere in the file (grep-gated and unit-tested). Not-editing state renders a `note-chip-slot-{n}` button: an empty chip shows an aria-hidden `Pencil` icon with `aria-label="Add note"`; a populated chip shows the note text (ellipsis-truncated, `aria-label="Edit note: {text}"`). Clicking opens a `note-input-slot-{n}` text input (`maxLength={NOTE_MAX_LENGTH}`, placeholder `"Note…"`, absolutely positioned so it never shifts layout) — Enter or blur commits via `writeNote` and truncates to 20 chars; Escape discards the draft. Both the button and the input call `e.stopPropagation()` on `pointerdown` so a future hand-drag gesture never starts from the chip. The chip's own flow height stays 20px (matching MarksZone's reserved note-row budget); an absolutely-positioned `aria-hidden` inset span (-12px vertical) expands the effective hit area to the touch-target minimum without growing layout, reusing the exact technique 06.1-10 established for the discard-toggle button.

**Task 2 — Wiring into `Hand.tsx`/`HanabiBoard.tsx`:** `OwnHand` gained a `roomCode: string` prop and now passes `noteSlot={<NoteChip key={card.id} roomCode seatId cardId slotNumber />}` into each own-hand card's `MarksZone` (only when `youSeatId` is non-null); `TeammateHand` was left untouched — no note affordance on teammate cards (D-03). `OwnHand`'s body still touches only `card.id` and `card.facts`, verified by the existing structural scan. `HanabiBoard` passes `roomCode={view.code}` to `OwnHand` and gained a cleanup effect keyed on the joined own-hand card-id string, `view.youSeatId`, `view.status`, and `view.code`: an ended game calls `clearNotesForRoom`; otherwise it calls `pruneNotesForSeat` with the current live card ids, deleting notes for any card that has left the hand (played/discarded), including across a reconnect after the tab was closed mid-game.
