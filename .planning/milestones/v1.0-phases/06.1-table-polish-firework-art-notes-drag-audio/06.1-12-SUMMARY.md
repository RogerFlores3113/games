# Phase 06.1 Plan 12: Own-Hand Drag (Reorder / Play / Discard) Summary

Mouse drag on the own hand, implemented with raw Pointer Events (no drag library): drag a card onto another own slot to reorder (works anytime, off-turn included, per D-17), drag onto the Fireworks stacks to play, drag onto the discard pile to discard (turn-gated), with legal-zone glow highlighting, inline disabled reasons for illegal zones, snap-back when dropped outside every zone, and a brief client-side optimistic reorder until the server's confirmed order lands.

## What Was Built

**`applyPendingOrder`** (`hanabi-drag-logic.ts`) applies a client-held optimistic card order over the server's `yourHand` array. It is defensive: a `pendingIds` list that isn't an exact permutation of the current cards (wrong length, or an id no longer in hand) returns the input array unchanged rather than dropping or duplicating a card — this matters because a reorder's optimistic order can go stale the instant a draw/play/discard changes hand membership before the server confirms the reorder itself.

**`useHandDrag`** (`components/hanabi/useHandDrag.ts`) is the drag engine: pointerdown on an own card (primary button only, blocked while reconnecting/ended) starts tracking and calls `setPointerCapture`; pointermove past the 6px threshold begins the visible drag and resolves the current drop target via `resolveDropTarget` against slot/play/discard rects rebuilt from `getBoundingClientRect` on every move; pointerup resolves the drop through `requestForDrop` — the single existing pure chokepoint that also backs the disabled-reason button logic — and calls `onDropRequest` exactly once if a request resulted (T-06.1-36: no duplicate sends). Nothing is ever sent from pointermove (D-18). The window-level listeners are subscribed once; the hook reads the latest `game`/`ctx`/`onDropRequest` through refs so a server frame landing mid-drag or a reconnect flip is honored without re-subscribing.

**`HanabiBoard.tsx`** widens `HanabiActionRequest` with `{ type: "reorder"; cardIds: string[] }`, calls `useHandDrag` unconditionally (moved `ctx` construction above the early `!game` return to keep hook order stable), passes `applyPendingOrder(game.yourHand, drag.pendingOrder)` as `OwnHand`'s `cards`, and computes a `dropStatus` object (via `dropZoneStatus` for both zones plus the currently-hovered target kind) only while a drag is active, threaded into `Table`.

**`Table.tsx`** attaches `playZoneRef`/`discardZoneRef` to the Fireworks stacks container (`data-testid="play-zone"`) and the existing discard-pile block, renders a `box-shadow: var(--color-card-glow)` highlight (stronger while hovered) on enabled zones during a drag, and an absolutely-positioned reason label (`drop-reason-play`/`drop-reason-discard`) above a disabled zone — both additions paint outside layout, preserving the UI-11 1280x720 no-scroll fit.

**`Hand.tsx`/`OwnHandCard.tsx`** thread the hook's props through each own-hand slot: `data-card-id` + a `registerSlot` ref callback per column for zone-rect building, `onCardPointerDown` wired to the card button, and a `consumeClickSuppression()` guard on the click handler so the click that follows a completed drag never also fires a select. `OwnHandCard` lifts while dragging (translate-by-offset + 1.05 scale, elevated shadow, `z-index: 50`, `pointer-events: none` on the moving layer so drop-zone hit-testing beneath it still works), gets `touch-action: none` and `cursor: grab`/`grabbing`, and a `drag-snap` transition class applied only while not dragging so a released card outside every zone eases back to its slot. No keyboard reorder handlers were added (D-19) — Play/Discard buttons remain the unchanged keyboard/click fallback.

**`globals.css`** gained `.drag-snap` (150ms ease-out transform transition) with a `prefers-reduced-motion: reduce` override to `transition: none`, matching the existing clue-touch/stack-flash motion pattern.

**`own-hand-source.test.ts`** was extended to scan `useHandDrag.ts` under the same D-15 structural rules as the other own-hand files (no `suit`/`rank` property access or destructuring, no `exposeSuit`/identity DOM markers, no `HanabiCardView` import) — the hook only ever handles card ids.
