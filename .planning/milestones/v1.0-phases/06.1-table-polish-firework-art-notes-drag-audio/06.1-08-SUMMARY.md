# Phase 6.1 Plan 08: Wire Audio Into the Board Summary

**Live history transitions now play synthesized clue/play/discard/fuse/stack-complete cues on every connected screen via a gesture-unlocked `useHanabiAudio` hook, with an icon-only mute toggle and volume slider added to the bottom controls row — completing AUD-01 end to end.**

## Accomplishments
- `useHanabiAudio(game, reconnecting)` computes `cuesForTransition` on every new game view and plays each cue through the injected `createAudioEngine()` instance, never touching Web Audio APIs directly
- Gesture unlock: `window` `pointerdown`/`keydown` listeners call `engine.unlock()` once and remove themselves immediately after, satisfying D-26 (no context creation before the first gesture)
- Reconnect baseline reset (D-29): `prevRef.current = null` whenever `reconnecting` becomes `true`, so the first view after a reconnect never plays a backlog of catch-up cues
- `AudioControls` renders an icon-only mute toggle (`Volume2`/`VolumeX` from `lucide-react`, `aria-label`/`aria-pressed`) and a 0-100 range input (`aria-label="Sound volume"`), both with 44px touch targets and the shared accent focus-visible outline, using only `--color-text`/`--color-text-muted`/`--color-border`
- `HanabiBoard` calls the hook unconditionally alongside its other hooks (before the `if (!game)` early return) and renders `AudioControls` after `CluePicker` in the bottom controls row; UI-11 (five players, 1280x720, no scroll) and RT-01 both stayed green with no layout adjustment needed
