## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| generated action sequences → engine | Property tests drive the same `applyAction` boundary a hostile client would, at scale |
| test helpers → engine rules | `enumerateLegalActions` must derive legality from the engine, or every property becomes self-confirming |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-20 | Information Disclosure | A leak reachable only through a state sequence no example test constructs | mitigate | Redaction property checks every seat's view after every step across 200 random games per variant, using the checker plan 04's canaries prove can fail |
| T-03-21 | Denial of Service | A rules bug producing a game that never satisfies any end condition, hanging a Phase 4 room actor indefinitely | mitigate | Termination property with a hard `MAX_SIMULATED_TURNS` bound whose breach fails the test rather than warning or skipping |
| T-03-22 | Tampering | Card duplication or loss through a state transition, silently changing the achievable score | mitigate | Card-conservation property locates every card in exactly one place after every step |
| T-03-23 | Repudiation | A property test that passes vacuously after a generator or fixture change | mitigate | Every guarded loop asserts a nonzero executed-step count (D-22/WR-02), and the variant sweep asserts it ran three times |
| T-03-24 | Elevation of Privilege | Test helpers re-implementing legality, letting an illegal-action bug pass unnoticed | mitigate | `test-support.ts` builds candidates and filters them through the exported `canPlay`/`canDiscard`/`canClue` predicates only; its header states the constraint |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No installs in this phase; `fast-check` 4.9.0 and `vitest` 4.1.11 are already exact-pinned and were audited when introduced |
