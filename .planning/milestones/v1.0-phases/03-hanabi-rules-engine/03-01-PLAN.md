<objective>
Build the variant-parametrization layer and the deterministic dealer for the Hanabi engine: the closed suit/rank sets, the single `VariantConfig` that is the only source of suit count and deck composition, the shared type vocabulary every later module compiles against, and a seeded dealer that reuses `shuffle.ts` unchanged.

Purpose: RULES-03 requires suit count to come from configuration, never a hardcode. Every later plan (legality, actions, projection) reads its suit/rank truth from this one object, which is what lets Phase 7 enable Rainbow and Black without restructuring the engine.
Output: `packages/rules/src/hanabi/{variant,state,deck}.ts` plus unit tests for variant config and deck construction, all three variants covered.
</objective>

```typescript
  readonly variant: Variant;
  readonly suits: readonly Suit[];
  readonly cluableColors: readonly Suit[];
  rankCountsFor(suit: Suit): Readonly<Record<Rank, number>>;

}
```

```typescript
import type { Variant } from "../adapter";
import type { Rank, Suit } from "./variant";

export type HanabiCard = { readonly id: string; readonly suit: Suit; readonly rank: Rank };
export type Clue = { readonly type: "color"; readonly value: Suit }
                 | { readonly type: "rank"; readonly value: Rank };

export type ClueFacts = {
  readonly possibleSuits: readonly Suit[];
  readonly possibleRanks: readonly Rank[];
  readonly positiveClues: readonly Clue[];
  readonly negativeClues: readonly Clue[];
};

export type HandSlot = { readonly card: HanabiCard; readonly facts: ClueFacts };
export type Hand = { readonly seatId: string; readonly slots: readonly HandSlot[] };
export type StackEntry = { readonly suit: Suit; readonly topRank: number }; // 0 = empty stack

export type HistoryEntry = /* defined in plan 02's history.ts and imported here */ unknown;

export type HanabiState = {
  readonly variant: Variant;
  readonly seatIds: readonly string[];
  readonly turnIndex: number;
  readonly hands: readonly Hand[];
  readonly deck: readonly HanabiCard[];
  readonly stacks: readonly StackEntry[];
  readonly discard: readonly HanabiCard[];
  readonly clueTokens: number;
  readonly fuses: number;
  readonly finalTurnsRemaining: number | null;
  readonly history: readonly HistoryEntry[];
};

export type HanabiAction =
  | { readonly type: "play"; readonly cardId: string }
  | { readonly type: "discard"; readonly cardId: string }
  | { readonly type: "clue"; readonly targetSeatId: string; readonly clue: Clue };

// View types are deliberately NON-readonly plain objects/arrays so HanabiView
// stays assignable to Phase 4's z.infer type (same split forehead-card.ts uses).
export type HanabiCardView =
  | { id: string; hidden: true; facts: ClueFactsView }
  | { id: string; hidden: false; suit: Suit; rank: Rank; facts: ClueFactsView };

export type ClueFactsView = {
  possibleSuits: Suit[]; possibleRanks: Rank[];
  positiveClues: Array<{ type: "color" | "rank"; value: Suit | Rank }>;
  negativeClues: Array<{ type: "color" | "rank"; value: Suit | Rank }>;
};

export type HanabiView = {
  variant: Variant;
  yourSeatId: string | null;
  yourHand: HanabiCardView[];
  otherHands: Array<{ seatId: string; cards: HanabiCardView[] }>;
  stacks: Array<{ suit: Suit; topRank: number }>;
  discard: Array<{ id: string; suit: Suit; rank: Rank }>;
  clueTokens: number;
  fuses: number;
  deckCount: number;
  finalTurnsRemaining: number | null;
  activeSeatId: string;
  isYourTurn: boolean;
  score: number;
  history: unknown[]; // HistoryEntryView[], concretized in plan 02
};
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| seed → engine | The server-only game seed enters `dealInitialHands`; it must never become a field of `HanabiState` and therefore can never reach a projection |
| variant name → config | A variant string selects a config; an unrecognized value must not silently produce an empty or partial suit list |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | `dealInitialHands` retaining the seed or PRNG state in returned state | mitigate | The returned shape contains only `hands` and `deck`; all card ids are minted up front so no RNG state is carried in `HanabiState` (asserted by state.ts having no `idRng`/`seed` field) |
| T-03-02 | Information Disclosure | Card ids correlating with deck position | mitigate | Ids come from `mintCardId`'s independent `"hanabi-card-ids"` stream; deck.test.ts asserts no id equals its unshuffled index and ids contain no digits (D-04) |
| T-03-03 | Tampering | A caller passing an unrecognized variant string | mitigate | `variantConfig` is exhaustive over the closed `Variant` union and throws on an unreachable default rather than returning a partial config; TypeScript exhaustiveness plus a unit test cover it |
| T-03-04 | Information Disclosure | PRNG internal-state recovery from observed shuffle effects (WR-01) | accept | Documented in deck.ts's header as an accepted residual risk: cooperative game, trusted friend group, no adversarial incentive; revisit before any public-room expansion |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No installs occur in this phase (`packages/rules` stays zero-dependency per FDN-02); RESEARCH.md's Package Legitimacy Audit records "not applicable — no installs" |
